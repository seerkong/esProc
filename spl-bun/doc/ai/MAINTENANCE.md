# 文档维护指南

## 文档结构规范

### RULE-DOC-001: index.md 仅作文件索引

每个 `index.md` 文件仅用作导航索引，不得包含具体说明或操作步骤。

**正确格式：**
```markdown
# 目录标题

简要描述（1-2句话）。

## 文档列表

| 文档 | 说明 | 何时阅读 |
|------|------|----------|
| [file.md](./file.md) | 简要描述 | 使用场景 |
```

### RULE-DOC-002: 禁止引用不存在的文件

所有文件引用必须指向实际存在的文件。先创建文件，再添加引用。

### RULE-DOC-003: 规范的表格格式

文档列表统一使用三列表格：`文档`、`说明`、`何时阅读`。

### RULE-DOC-004: 规则命名规范

规则使用 `RULE-<SCOPE>-<NUMBER>` 格式：

| Scope | 含义 |
|-------|------|
| ARCH | 架构规则 |
| EXPR | 表达式引擎规则 |
| FLOW | 流程控制规则 |
| CORE | 核心模块规则 |
| DOC | 文档规则 |

## 分形子目录结构

每个主目录采用相同的 6 个子目录结构：

| 目录 | 作用 | 包含内容 |
|------|------|---------|
| `introduce/` | 概念和知识介绍 | 概述、架构图、术语定义、背景知识 |
| `howto/` | 操作步骤和指南 | 开发流程、操作指南、最佳实践 |
| `example/` | 代码示例 | 实体定义、控制器、组件、API 样例代码 |
| `constaint/` | 规范和约束 | 架构规则、开发规则、命名规范 |
| `misc/` | 补充信息 | 主题系统、静态资源、特殊配置 |
| `troubleshooting/` | 问题解决 | 常见问题、错误诊断、解决方案 |

## 更新流程

1. 修改代码后，检查是否需要更新相关文档
2. 新增功能时，在对应模块目录下添加文档
3. 修改 API 时，更新 example/ 目录下的示例
4. 发现问题时，在 troubleshooting/ 目录下记录解决方案

## 文档来源

本文档内容主要来源于：

1. `codument/archive/` - 已完成的设计文档
2. `codument/tracks/` - 进行中的设计文档
3. `packages/*/\_\_tests\_\_/` - 测试用例（行为规范）
4. 源代码注释和类型定义
