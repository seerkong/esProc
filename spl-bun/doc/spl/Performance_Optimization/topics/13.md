有序与补充文件
即使存储量没有减少，有序存储对搜索和遍历也很重要。
我们将在后面逐步讨论如何利用有序性提升操作性能。

=file("data1.ctx").create(#K1,#K2,…)
创建复合表时，若参数中的字段名以 # 开头，表示复合表将按这些字段排序（按字段顺序，且必须是前几个字段）。但 SPL 在追加时不做校验，程序员需确保写入数据确实有序。
有序存储的麻烦主要在于数据追加。新追加的数据不一定与原有数据有序衔接。例如复合表当前按 ID 字段排序，而新追加数据的 ID 往往是同一批值。为保证复合表整体按 ID 有序，需要重新按 ID 排序所有数据，无法简单追加到末尾。大数据排序是非常耗时的动作。
SPL 提供两种方式获得完全有序的新复合表。

append@m() 表示使用归并算法，将原有复合表与游标中的新数据一起排序生成新复合表。原复合表已排序，若新数据游标也有序，可采用低成本有序归并算法。总体复杂度相当于把所有数据读写一遍，避免普通大排序中的大量临时文件，从而获得更好性能。
然而对大数据而言，通读写一遍仍然耗时。SPL 还提供补充文件机制，以得到逻辑上有序的新复合表。

SPL 为每个有序复合表建立两个存储文件，一个主文件，一个补充文件。使用 append@a() 追加有序数据时，追加数据与补充文件合并，主文件保持不变。使用 reset() 时，主文件与补充文件合并形成更大的主文件，并清空补充文件。
从上述代码可见，当日期为 1 号时执行 reset 合并主文件与补充文件；其他日期使用 append@a() 将数据合并到补充文件。若每天追加一次新数据，补充文件最多存一月的数据，早于一月的数据都在主文件中。也就是说主文件可能很大而补充文件较小。这样每日合并量不大，数据追加可快速完成，而每月一次整理全量数据会耗时更久。
SPL 访问复合表获取数据时，会分别读取主文件和补充文件，然后归并返回（保证返回结果仍有序），逻辑上等同于一个复合表。它比访问单文件略慢，但仍能利用有序性。
