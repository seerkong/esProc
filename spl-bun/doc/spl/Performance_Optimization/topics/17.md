3.2
哈希索引
使用二分查找时仍需多次读取原文件以定位目标值，过程中有不少冗余读取。若能高效获取目标值的物理位置，就可直接读取目标值。
在待查键（TBS key）值与目标值物理位置之间建立关联表，通过查询值从关联表中快速得到物理位置，再读取目标值。该关联表即外部存储索引。
索引中有大量 TBS key 值，需要对索引本身进行类似数据表的检索。区别在于可专门设计索引结构以便快速搜索。
哈希索引会对原数据表中的 TBS key 值计算哈希值，按哈希值存储 TBS key 值及其对应记录的物理位置，把相同哈希值的记录放在一起。
通常原数据表很大，索引也太大无法全放内存。这时需为索引本身建立小索引。哈希值范围事先已知，可分段存储，比如哈希值 1-100 为一段、101-200 为另一段，以确保每段足够小可加载到内存。在索引头保存固定长度的小索引，记录每段存放的哈希值范围及该段的物理位置和长度。确定查询值后先计算哈希值，读取小索引确定下一步搜索的段，此时可用内存检索技术。通常每段哈希值有序存放，可用二分查找；若每段哈希值数量固定，也可用序号定位。再读出该段，查找目标值的物理位置（同样为内存检索），然后从原数据表读出。
总结为三步：先读取头部小索引，再读取查询值所在的索引段，最后通过物理位置读取目标值。这样总共只需读取三次，索引相对二分查找优势明显。并且小索引读入一次后可常驻内存，后续无需重复读取，读取量可进一步减少。
当数据量极大时，头部小索引可能过大无法加载内存，此时需为小索引再建更小索引，即索引可分多级。用加载顺序表示索引级别，最先加载的最小索引称一级索引，通过一级索引找到二级索引，再到三级、四级（四级已足够大）。最后一级定位目标值物理位置。每次搜索最大读取次数等于索引级数加读取目标值一次。一级索引可驻留内存避免重复读取。
哈希索引另一个问题是哈希函数可能运气不佳，导致某段哈希值对应记录过多存入同一索引段。此时需进行第二轮哈希，更换哈希函数重新分布这些记录。若仍不佳可能第三轮、第四轮……。因此哈希索引层级不固定，某些查询值可能层级更多。
整个过程并不简单，外部存储任务确实比内存任务麻烦得多。

理论上也可按记录序号与物理位置建立索引，从而逻辑上实现序号定位的效果。但通过上述分析可知，外部存储检索的时间成本主要在索引分段及多级索引处理。即使采用序号定位也需同样过程，内存操作中的序号定位节省时间在这里已不明显，因此外部存储检索不再特别提出序号定位方法。
