3.7
返回集合的检索
有时需要为一个检索值找到多个目标值，例如通过用户 ID 查找该用户的交易记录。
为用户 ID 建索引可以避免全表遍历并提升检索性能，但这还不够。如果外部存储数据表中多个目标值的存储位置不连续，即使通过索引能快速定位目标位置，实际读取仍会在硬盘上跳转。并且硬盘读取有最小单位，这个单位通常远大于单条记录所占空间，导致读出的内容大多浪费（列式存储更严重）。机械硬盘频繁跳转也会消耗大量时间，尤其该检索往往伴随并发，会进一步加剧硬盘跳转。
解决方案是按待检索键（TBS key）预先排序并存储数据，使同一检索值对应的目标值在物理上连续存放。这样读出的数据块几乎都是所需目标值，不会引起硬盘跳转，性能提升非常明显。

重新生成一个按 ID 排序的复合表。每个 ID 下可能有多条记录。创建索引后，检索方式与之前无异，但性能更好，尤其在并发场景下。使用行式存储或值索引也会比直接使用列式存储更好。你可以生成一个无序复合表来对比性能差异。
再强调一次：即使数据表已按 TBS 键排序，建立索引仍有意义。索引能直接定位目标位置，不同于外部存储的二分检索会读出相邻数据尝试判断。
这类交易数据的生成顺序通常是时间，而 TBS 键通常不是时间。这就需要将持续生成的新数据（按时间顺序）追加到现有数据表中，并按 TBS 键维护有序，从而获得高性能检索结果。这将使用前一章讨论的补充文件方法来实现追加并形成有序复合表。
