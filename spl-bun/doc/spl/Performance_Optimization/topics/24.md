# 3.9 全文检索

- 格式：为 AI 阅读提取的 Markdown

## 类代码片段
```spl
=file("data.ctx").open()
=A1.index@w(IDW;X)
=A1.icursor(like(X,"*abc*"))
```

## 提取内容
3.9
全文检索
在结构化数据查询中，经常需要检索字符串字段包含某个子串的记录。如果条件是 like(X,"abc*")，即子串位于字段开头，可以利用该字段的索引快速定位。因为满足 like(X,"abc*") 的记录在 X 的排序索引中是连续存放的，我们可以用子串 abc 快速定位第一条记录（或迅速判定不存在），然后继续遍历直到条件不再满足。该机制已在 SPL 中实现，当发现这种条件时，会检查 X 是否有排序索引并加以利用。
若子串位于被检索字段的中间，即 like(X,"*abc*") 形式，就无法使用上述索引，需要为文本建立索引。
面向搜索的全文检索当然可以解决这个问题，但其索引过大（因数据量也更大），并且可能涉及专业的自然语言理解与分词技术，不适合引入结构化数据计算任务。
结构化数据规模远小于搜索引擎面对的网页，检索范围通常限制在某个字段，因此涉及的数据量更小。而字段内容通常是几个字符到一句话，很少是整篇文章。在这种情况下，可以使用更简单的技术。
将字段（字符串）拆分为字符，取所有出现过的两字符（或三字符）组合。例如字符串 abcd，可得到 ab、bc、cd 的组合，然后为这些组合建立排序索引。待检索键为这些字符组合，对应出现该组合的记录。
这样建立的索引不会很大。常用字符（中文字符和英文字符）约为数千个，若取两字符组合，最多是数千乘数千，约一百万到一千万；若取三字符，可能是数十亿级，现代较好的服务器也能支持。
再看如何检索。以两字符组合为例，继续沿用上一节的符号。
容易证明 S(like(X,"*abc*")) Í S(like(X,"*ab*")) Ç S(like(X,"*bc*")).
利用该索引，可轻易找到 S(like(X,"*ab*")) 与 S(like(X,"*bc*"))，再用上一节的索引合并技术求交集得到 S(like(X,"*ab*")) Ç S(like(X,"*bc*"))，随后在该集合中进一步判断 like(X,"*abc*") 是否成立，得到最终目标值（目标值包含于该集合，但不一定相等）。无论如何，这能显著减少计算量，且不需要高成本的全文检索技术。
这种简化的全文索引已在 SPL 中实现：
|
=file("data.ctx").open()
|
=A1.index@w(IDW;X)
|
=A1.icursor(like(X,"*abc*"))
使用 index@w() 会建立该索引。当前使用双字符方案，在很多场景已足够。检索时可以直接使用 like 作为条件。
