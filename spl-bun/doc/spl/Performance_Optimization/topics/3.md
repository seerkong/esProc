二分查找
内存中的表序列 T 有字段 K，给定查找值 k，在 T 中找出字段 K 的值为 k 的记录。字段 K 称为待查键，找到的记录称为目标值或目标记录。
传统的顺序查找会依次遍历 T 的每个成员进行比较。若 T 中有 N 条记录，平均比较次数为 N/2，复杂度为 O(N)。如果 T 已按 K 排序（序列 T.(K) 或 T.(-K) 为递增序列），则可以使用二分查找。
在进一步介绍算法之前说明：本书讨论的大多数算法对表序列和记录序列通用，甚至对一般序列也有效。但有时使用某个术语来描述更为方便。只要理解原理，就可以扩展到类似场景。在应用这些算法时，不必严格遵守书中描述的前提与场景，而是理解原理后再确认当前场景是否适用，必要时做少量修改。
二分查找是常见算法。以 T.(K) 升序为例，其基本逻辑如下：
|
=1
|
=T.len()
|
for
|
=(A1+B1)\2
|
=T(B2)
|
if k==C2.K
|
return C2
|
else if k>C2.K
|
>A1=B2+1
|
else
|
>B1=B2-1
|
if A1>B1
|
return null
将 k 与 T 的中间成员比较，若不相等，则按比较结果排除一半成员，并在剩余的一半子集上继续该操作，直到找到目标值或剩余子集为空。因为每次可排除一半成员，最多比较 log 2 N 次即可找到目标值（或确认找不到），复杂度为 O(logN)。当 N 较大时，相比顺序查找优势明显；当 N 较小时，由于二分查找过程较复杂，可能比顺序查找更慢。通常 N>=8 时，二分查找有优势。
若 T.(K) 存在重复值，可能有多个目标值。用二分查找找到一个目标值后，需要向前向后继续比较更多记录。平均重复次数为 M 时，每次查找平均多 M 次比较，总复杂度为 O(logN+M)。通常重复值只是偶发，即满足 M ≪ log 2 N，复杂度仍可视为 O(logN)。若重复值很多，则在复杂度分析中 M 不能忽略。顺序查找的复杂度无论是否重复都为 O(N)。重复值存在时，二分查找的复杂度一般仍更低，但实践中需要更大的 N 才能体现优势。
SPL 提供二分查找选项，可直接使用：
|
=10000.new(string(~,"00000"):id,
~\3:K).keys(id)
|
=A1.find@b("01234")
|
=A1.select@b(K:1234)
|
=A1.select@b(K-1234)
|
=A1.pselect@b(K:3210)
|
=A1.pselect@b(K-3210)
find@b() 按主键查找，找到一个即返回。select@b() 会按存在重复值的情况处理，pselect@b() 默认只返回一条，但会找到第一条，也考虑重复值。
需要注意的是，select@b() 和 pselect@b() 的参数不能使用逻辑表达式，而应使用冒号分隔符或返回数值的表达式，因为逻辑表达式只能计算出真/假值，无法在不等时确定下一步查找方向；数值表达式为 0 表示找到，<0 与 >0 用于表示下一步查找方向。
可以用 SPL 比较二分查找与顺序查找的性能差异。
还需提醒，使用二分查找需要事先有序。排序是很慢的操作，不能为了临时使用二分查找而先排序，只会更慢。通常需要多次在表序列中查找，在这种情况下先排序，再进行多次查找才能获得更好性能。
