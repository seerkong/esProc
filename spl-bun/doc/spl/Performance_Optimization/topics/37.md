## 提取内容
5.3
程序游标
继续使用上面的例子。现在我们要找出每个月内连续 n 天发生交易的记录，然后按发生日期的星期几统计交易金额。
后一个任务很简单，是常见的分组聚合操作。前一个任务则较麻烦。即便数据表按账户与日期排序，要完成该复杂操作仍需先取出分组子集，再写几行代码筛选结果。之后这些记录会存入内存，那么如何继续进行分组聚合？
一个容易想到的方法是把计算数据逐步写入缓冲文件，再对该文件做分组聚合：
|
=file("trades.ctx").open().cursor(id,dt,amount)
|
for A1;id
|
=A2.align@a(31,day(dt)).group@o(~==[])
|
=B2.select(~.len()>=n ).conj().conj()
|
=file("temp.btx").export@ab(B3,dt,amount)
|
=file("temp.btx").cursor@b().groups(day@w(dt);sum(amount))
A2 取出每个分组子集；B2 按交易日期对齐到 31 天，再用有序分组将其拆成连续为空与非空的子集；B3 找出跨度超过 n 的子集，此时可得到连续 n 天有交易或无交易的记录，并将其并集得到连续 n 天有交易的记录（连续 n 天无交易的是空集，不会影响并集结果）。注意这里需要 conj 两次，因为 align@a 的结果是序列的序列。
计算完成后，将结果写入临时文件，只需写两个字段，最后再做分组聚合。
显然，这一过程因为写读文件会很慢，需要把中间数据写入缓冲文件。实际上，这些数据可直接用于分组聚合，无需写入外部存储。但分组函数只能基于表序列或游标，如果硬编码每批数据来分组聚合，会过于麻烦。
SPL 提供程序游标机制，允许我们将循环中产生的数据模拟为游标。
|
Func
|
=file("trades.ctx").open().cursor(id,dt,amount)
|
for A1;id
|
=A2.align@a(31,day(dt)).group@o(~==[])
|
return B2.select(~.len()>=n ).conj().conj()
|
=cursor@c(A1).groups(day@w(dt);sum(amount))
通过定义子程序，可在该子程序的循环中计算并返回所需记录。cursor@c() 会收集这些返回值并拼接成游标。当从游标取数（如这里的 groups()）时，cursor() 函数会执行子程序并收集返回值。一旦收集到的值足够满足本次取数，就暂停子程序执行并返回结果，但子程序不会结束。下一次取数时子程序继续运行，直到循环结束，此时 cursor() 也返回游标结束信号。
该过程可将循环中连续计算的数据拼接为游标，无需把中间数据写入文件，因此复杂过程也能获得更高性能。这种游标称为程序游标。
如前所述，SPL 为大分组提供了哈希方法，但没有提供类似的排序算法。我们可以用程序游标机制实现一个粗略版本，例如按订单金额排序订单表：
|
func
|
=file("orders.btx").cursor@b()
|
=100.(file(~ ） )
|
=B1.groupn(int(amount/100)+1;C1)
|
>B1.skip()
|
for C1
|
return B3.import@b().sort(amount)
|
return cursor@c(A1)
在 B2 中按金额将订单分成 100 份（这里假设金额大致均匀分布在 0-10000 范围内，可根据实际情况调整分割方式。需要保证分割表达式与排序字段值单调不减或单调不增，并且每个分割值对应的记录数量足够小可装入内存）。然后按顺序返回每一份的排序结果，cursor@c() 会收集这些返回值并拼接成游标。
