1.2
序号定位
有时待查键的值正是目标值在表序列中的序号（即位置），或可以通过查找值容易计算出目标值的序号。这时可以使用序号定位法。
|
=10000.new(~:id, … )
|
=A1(1234)
|
=10000.new(string(10000+~-1):id, … )
|
=A3(int("12345")-10000+1)
|
=10000.new(date(1999,12,31)+~):dt, … )
|
=A5(now()-date(1999,12,31))
|
=A5.groups(month@y(dt):ym; … )
|
=month&y(now())
|
=A7((A8\100-2000)*12+A8%100)
A1 的 id 字段本身就是序号值，可直接用查找值作为位置找到目标值。A3 的 id 字段也是由连续数字转换而来的字符串，查找时应反向计算序号。序号定位常用于日期相关查找。日期或月份通常是连续值，容易通过运算对应到序号。A5 的 dt 字段是有序日期，从起始日期起的天数就是目标值的序号。A7 以年月为序号，计算稍复杂。
定位序号不需要比较，只需计算一次序号，复杂度为 O(1)。
在上述 A5 或 A7 中，我们生成数据时保证每个序号都有对应日期，但实际业务数据可能存在空缺日期，若仍采用序号定位将发生错位。
|
=10000.new(date(2000,1,1)+rand(10000)):dt, … )
|
=A1.groups(dt; … )
|
=A2(now()-date(1999,12,31))
|
=A2.align@b(10000,dt-date(1999,12,31))
|
=A4(now()-date(1999,12,31))
A1 生成的日期不能保证覆盖对应期间的每一天，因此 A2 可能有缺失日期，A3 用序号定位会出错，返回的数据可能不是当天的数据。对 A4 使用 align() 后，可确保某一天的记录落在对应序号位置上，A5 就能用序号定位找到它。对于缺失日期，align() 会在对应位置填入 null。这样，若查找值对应的目标值不存在，将返回 null，可判断是否找到目标值。align() 的 @b 选项表示在对齐时使用二分查找定位位置，从而加快对齐。
与前面提到的排序类似，对齐相对序号定位是更慢的操作。不能为了临时查找而先对齐再用序号定位。只有需要反复多次查找时，才应先对齐，以便后续查找获得更高性能。
将待查记录按序号对齐后即可使用高效的序号定位，似乎只要能把查找值计算成序号即可。
当然不是。例如中国公民身份证号码由一系列数字组成，可理解为自然数，看似天然是序号。但不能将身份证号按自然数对齐后再使用序号定位。序号定位需要长度不小于最大序号的序列来存放所有记录及填补空缺的 null。若将身份证号直接转为自然数，序号范围大到当前计算机内存无法承受（10 17，身份证号为 18 位，末位校验位不计），需要填充的空序号远多于有记录的序号，这种情况下不能直接使用序号定位。
