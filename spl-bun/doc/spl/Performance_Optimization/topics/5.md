位置索引
有时我们需要找到表序列中目标值的位置，而不是目标值本身。如果表序列在待检索键（TBS key）上是无序的，就不能用二分查找提升性能。预先按 TBS key 排序后可以二分查找，但目标值在原表序列中的位置信息会丢失，所以无法完成搜索任务。
例如，某登录系统记录一组用户的登录时间和用户 ID，并按登录时间排序。现在我们想知道指定 ID 的用户登录之后，在多长时间内没有其他用户登录。
如果能找到该用户登录记录在数据表中的位置，只要取下一条记录计算时间差即可完成任务。然而原始数据并未按用户 ID 排序，只能顺序查找，速度很慢；若按用户 ID 排序，又会丢失位置。
使用位置索引可以解决这个问题：
|
=10000.sort(rand())
|
=20000.sort(rand()).to(10000)
|
=A1.new(elapse@s(now(),-B1(#)):tm,~:id, … )
|
=A2.psort(id)
|
=A2(A3)
|
=B3.pselect@b1(id:1234)
|
=A2.calc(A3(A4),tm[1]-tm)
这段代码稍显曲折，需要仔细理解。
当 B3 按用户 ID 获取有序记录序列时，在 A3 中保留 psort() 返回的位置序列。这样，A4 用二分查找在 B3 中找到目标值的位置后，可以用 A3 计算目标值在原表序列 A2 中的位置，再用定位计算完成任务。搜索过程（A4 和 B4）使用一次二分查找和两次序号定位搜索，整体复杂度相当于二分查找，远快于在原始集合上直接顺序查找。
