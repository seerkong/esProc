8.5
标志位维度
标志维度，也称二值维度，是只有两个取值（是/否或 true/false）的枚举型维度，例如是否已婚、是否上过大学、是否有信用卡等。
标志维度非常常见，对客户或对象打标是当前数据分析的重要手段。这类维度很少用于分组聚合，通常用于切片条件。
现代多维分析的数据集常常包含数百个标志维度。如果像普通字段一样处理如此多的维度，无论存储还是计算都会造成大量浪费，也很难获得高性能。
标志维度只有两个值，只需 1 个比特即可存储。16 位小整数可以存 16 个标志，因此用一个字段即可存下原本需要 16 个字段的标志。这种存储方式称为标志位维度，可显著减少存储量，也就是磁盘读取量。而且小整数不会影响读取速度。

设 n 为标志维度数量，标志维度命名为 tag1、tag2……A3 将生成 new() 函数的部分参数，用以把常规布尔标志维度转换为用 bits 表示的数据。每 16 个 tag 组成一个小整数，分别命名为 bits1、bits2……因此 bits1 对应原来的 tag1 到 tag16，bits2 对应 tag17 到 tag32，依此类推。在本代码中，为简化起见假定 n 是 16 的倍数，A4 中 new() 的 … 部分表示其他字段，直接照抄即可。
在实践中，字段的命名与排列方式可能不同，标志维度的数量也不一定是 16 的倍数，但可以参考此代码重写自己的实现。
通常标志维度会有多个切片条件，此时会取出这些标志维度都为 true 的记录。从标志位维度角度看，就是同时选出使这些标志位都为 1 的记录。这一判断也可以用位运算完成。

条件 tags 是由标志字段名组成的逗号分隔字符串，例如 "tag3, tag8, tag23"，表示选出这三个标志维度值都为 true 的数据。A2 解析序号并分组，每个分组对应一个新的标志位维度；A3 计算每个分组对应的标志位维度的值。例如，tag3 和 tag8 归为一组，对应 bits1，A3 计算出的值为二进制 0000000010000100（低位在右，从右往左数第 3 位和第 8 位为 1）；A4 取出序号不为 0 的分组，也就是需要判断的位维度序号（序号为 0 的不需要判断）；然后在 A5 中，将这些值转换为标志位维度条件，例如对 tag3 和 tag8 对应的分组，其条件为
and(bits1,132)==132
（132 是上述二进制的十进制值）
and() 函数是按位与运算，可判断 bits1 的第 3 位和第 8 位（从右往左数）是否都为 1。对应到原始标志，就是判断 tag3 与 tag8 是否同时为 true。因此这次运算即可完成两个标志条件的判断。
标志位维度能有效减少存储量，并且在多数情况下，可把多个 tag 的判断合并为一个位维度，大幅提升性能。对内存计算而言，这种方式还能显著减少内存占用，并在一定程度上减少判断次数，也很有意义。
