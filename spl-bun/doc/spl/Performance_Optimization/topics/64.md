## 提取内容
9.1
计算与数据
分布
当数据量很大时，可以用多台机器分担计算任务，即集群。在集群中，参与计算的机器称为节点机器，通常会有一个控制程序负责管理、分配各节点的计算任务并汇总结果，这个程序称为主控机。
节点一般是物理机器，因为逻辑机器无法分担计算任务。主控机主要负责控制，并不承担太多计算，因此可能是逻辑机器。某个节点上的线程或集群外的应用也可以充当主控机。
多机并行计算与单机多线程类似，只是把分配给线程的任务改为分配给节点。
SPL 的 fork 语句也支持多机并行计算，但需要在每个节点启动 esProc server 并提前配置访问地址。
|
["192.168.0.101:8281","192.168.0.102:8281",…,
"192.168.0.104:8281"]
|
fork to(4);A1
|
=file("orders.ctx").open().cursor(area,amount)
|
return B2.groups(area;sum(amount):amount)
|
=A2.conj().groups(area;sum(amount))
由于一年订单表很大，我们按季度分成 4 份并分别存到 4 个节点上，每一份使用相同的文件名（内容不同）。A1 是 4 个节点的访问地址（地址最后一段用于表示节点编号）。A2 中的 fork 语句把代码块发送到节点上的 esProc 执行。各节点执行完后把返回值传回主控机。主控机收集所有节点的返回值后继续向前执行，直到最终聚合完成。
在节点上也可以使用多游标并行计算：
|
["192.168.0.101:8281","192.168.0.102:8281",…,
"192.168.0.104:8281"]
|
fork to(4);A1
|
=file("orders.ctx").open().cursor@m(area,amount;;4)
|
return B2.groups(area;sum(amount):amount)
|
=A2.conj().groups(area;sum(amount))
这样可用多台机器分担计算任务并提升性能。
一般而言，集群中各节点的物理配置相同，计算能力也基本一致。上述示例将一年数据按季度划分到 4 个节点上，算是比较均衡的分布。这样每个节点遍历的数据量几乎相同，不会出现某个节点负担过重导致其他节点等待的情况。
如果需求改为先按指定时间段过滤订单表再分组聚合，情况就不同了。
假设时间段在第一季度，且数据按日期有序（通常如此），满足条件的记录可以利用数据的有序性快速定位。结果是 102、103、104 会迅速发现自己无事可做，几乎全部任务集中在 101。
采用蛇形分布可以避免这个问题。假设每天数据量差别不大，用日期对 4 取余决定数据分配节点，即第 1、5、9…天的数据放在 101；第 2、6…天放在 102；……第 4、8…天放在 104。这样执行上述需求时，就不会出现明显的任务不均衡。
理论上这会带来新的不均衡。例如统计第 1、5…天的数据时，任务会全部集中在 101。但在实际业务中几乎不会有这样的计算需求。对大多数应用场景而言，蛇形分布优于顺序分布。
合理的数据分布方案应根据计算目标设计，不存在能适配所有操作的方案。
