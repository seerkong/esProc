3.4 无限循环

如果 for 后面什么都不写，既没有循环次数也没有循环条件，会发生什么？

这种循环称为无条件循环，俗称无限循环。理论上，这个循环将无休止地执行，永远不会停止，就像不与 if 一起使用的 goto 一样。

这显然没有意义。我们不应该写一个无法终止的程序。

然而，在现实中看到无限循环代码并不少见。这是怎么回事？

因为我们还有 break 和 if。

无限循环并不是真正的无限循环，只是当我们写循环语句时，我们不确定如何写循环的结束条件。它需要在循环体的运行过程中确定。在这种情况下，我们会在循环开始时写一个无限循环，并在循环体中使用 if 来判断循环的结束条件。如果为真，我们将使用 break 跳出循环。

真正的无限循环确实没有意义。然而，如果用于触发 break 的 if 写错了，伪无限循环可能会变成真正的无限循环，编码时应该特别注意这一点。

设置一个四位数 x，分别拆分四个数字，用这四个数字组成最大的四位数 a，然后组成最小的四位数 b。这里，我们也把前几位是 0 的数（实际上是三位数、两位数甚至一位数）视为合理的四位数。然后计算 a-b 得到一个新的四位数，把它当作 x 并重复这个过程，这样计算可以无限重复。

如果在某一轮计算中新的 x 与之前的 x 相同，显然如果继续计算，只会出现相同的 x，继续下去没有意义。

我们把此时的 x 称为"数字黑洞"，一旦出现黑洞数，运算就可以停止了。

到目前为止，我们已经知道了几种控制程序流程的结构：

1）顺序结构：从上到下执行
2）分支结构：根据条件确定不同的方向，会跳过一些代码，整体方向仍然是向前的
3）循环结构：重复执行一段代码，包括由 goto 形成的循环

如果我们不考虑函数调用，可以说所有编程语言都只有这几种流程结构。我们已经全部学完了。

如果我们回顾一下我们做过的例子，会发现编程语言并没有帮助我们找到解决问题的方法。当我们遇到问题时，我们仍然需要自己想出解决方案，即通过一系列步骤（使用上述三种基本结构的组合）来解决问题，这些通常被称为算法。

编程语言的功能是提供一种方式来描述人类想出的算法，以便计算机能够理解和执行。好的编程语言可以更简洁地描述人们的想法，编程会很快；糟糕的编程语言可能非常麻烦，想出解决方案的描述可能比想出问题的解决方案更困难。

无论如何，不要指望编程语言帮助我们想出算法。如果您想不出算法，问题就没有解决方案。
