我们在这个类似 Excel 的网格中编写 SPL 代码，但这当然不是 Excel。

大多数编程语言只支持文本样式的代码。通常，如果没有特殊代码来改变顺序，代码会从前到后执行。SPL 略有不同。SPL 代码写在网格中，稍后将称为单元格集，其中所有单元格都填充代码并从前到后执行。具体来说，是逐个单元格执行的。每行中的每个单元格从左到右执行，然后执行下一行的单元格。虽然本质上没有区别，但网格样式的编码对非专业人员更友好，随着您对 SPL 的深入了解，您会更加体会到这一点。

编程书籍习惯于从一个简单的"Hello,World"示例程序开始，这是早期命令行时代的遗留产物，对于当代 GUI 操作系统来说已经是多余的了。我们就省略它吧。

执行前，代码区域的背景是白色的，点击包含代码的单元格不会在右侧部分显示值。与 Excel 不同，esProc 不会自动计算。通常，计算机程序不会自动执行操作，直到特殊的执行操作告诉它们这样做。

看看那些计算结果：

像 Excel 公式一样，esProc 公式用 * 表示乘法，用 / 表示除法，并按照先乘除后加减的顺序进行计算。

像 Excel 公式一样，esProc 公式中的每一层都用圆括号表示，而不是方括号或花括号，如果使用错误的符号会报错。

同样像 Excel 公式一样，esProc 公式可以计算正数和负数。

A1、B1 和 A2 的结果是不带小数点的整数。B2 和 B4 的结果是带小数点的整数，如 3.0 所示。为什么后者有小数点而前者没有？

因为计算机将带小数点的数字和整数识别为不同类型的数字。前者是浮点数，后者是整数。

我们在做算术时不关心数字的类型。但在计算机程序中，识别数据类型是首要的基本任务，对于获得正确结果至关重要，因为整数和浮点数的存储和处理方式不同。

既然我们可以把整数当作小数部分为 0 的浮点数，那有必要区分整数和浮点数吗？为什么不直接使用浮点数呢？

从数学上讲是可以的。但计算机执行相关操作时存在技术问题。由于存储和计算整数比处理浮点数简单得多，以浮点格式处理整数与处理真正的浮点数一样低效。因此，特别是当计算主要涉及整数时，这不是一个明智的选择。由于计算机无法知道区别，程序员需要做出正确的决定。

大多数编程语言区分整数和浮点数，但允许它们出现在同一个表达式中。为了计算表达式，我们会将整数转换为浮点数（整数总是可以转换为浮点数，反之则不行）。除法运算的结果可能是浮点数，因此 SPL 规定商应始终为浮点格式，以确保结果的数据类型明确且确定。SPL 还定义了一种返回整数的除法运算。这种除法用反斜杠（\）表示。如果您感兴趣，可以看看 =6\3 和 =5\3 分别会得到什么。

让我们继续查看 A6 的计算结果。它是 0。发生了什么？

大数字需要更大的空间来存储。然而，计算机的内存是有限的。机器无法表示无限大的数字。因此我们对数据大小设置了限制。大多数当代编程语言对整数有两种表示方式——32 位二进制整数和 64 位二进制整数。这意味着计算机能表示的最大数字是 2^32 或 2^64（实际大小要小一半，因为另一位用于表示负数）。一旦计算结果超过限制就会发生错误。

SPL 能处理的最大整数是 64 位。65536^4 超过了限制，所以发生了错误。不幸的是，几乎所有编程语言，包括 SPL，都不会报告这个错误，而是任其发生。程序员只能依靠自己来避免这个错误。

为什么选择 32 位整数和 64 位整数？两个最重要的原因是可用性和效率。32 位整数对于大多数操作来说已经足够，64 位整数占用太多空间且计算效率较低，这使得它们只在某些少数场合才有必要，16 位整数通常不够用，而发明另一种类型的整数会使列表有点拥挤（实际上 16 位整数甚至 8 位整数曾在早期计算机上使用过。有趣的是，所有这些类型的整数都是 2^n 位的。从来没有过 18 位或 25 位这样的位数）

像其他当代编程语言一样（早期编程语言可能有不同的约定），SPL 将 32 位数字称为整数，将 64 位数字称为长整数。

事实上，2^31 和 2^63 都是非常大的数字。由于很少使用这么大的数字，深入研究并不那么重要。

A7 的计算结果也不是我们期望的。为什么？

与整数一样，浮点数的存储空间也是有限的。另一方面，浮点数是有限的（约 ± 10^308），只能用大约 18 位有效数字的有限精度来表示（多余的数字应该被丢弃）。因此 A7 的错误发生了。

此外——这很重要，当代计算机使用二进制数进行计算。十进制整数的二进制对应物可以保留原始精度。但十进制有限小数，如 0.1，可能变成循环小数——您可以自己想想背后的原理——转换为二进制数后无法被计算机精确表示。当不精确的数字经过一系列运算时，偏差可能会累积导致意外错误。

然而，整数在一系列运算后始终是精确的，因此在所有可能的场合都是首选。

让我们看看 A8。与 A6 不同，它将 65536 记录为 65536.0，这告诉计算机这是一个浮点数而不是整数。SPL 会将数字转换为浮点格式，其范围远大于整数，进行计算以获得正确结果，而不是超出限制的数字。

但 1.8446744073709552E19 是什么意思？

这是所有编程语言通用的科学记数法。这里它表示数字 1.8446744073709552*10^19。在单元格代码中，数字 1.23*10^-20 也可以表示为 1.23E-20。

除了整数、长整数和浮点数之外，SPL 中的其他数据类型还包括大数（可以表示任意长度和精度的数字，但处理速度较慢）、字符串以及日期、时间和日期时间。所有这些都将在后续章节中出现。

理解基本数据类型是学习编程语言的首要任务。
