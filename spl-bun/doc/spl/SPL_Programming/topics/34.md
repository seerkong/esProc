### 7.2 拆分和连接

我们已经用循环函数和 mid() 把字符串拆分成单字符序列。因为这很常见，SPL 提供了 split() 函数。s.split() 等价于 len(s).(mid(s,~,1))。

split() 还有更多的字符串拆分功能。

但是，在讲 split 之前，让我们先学习一个 clipboard() 函数。

找一个文本编辑程序，比如记事本，输入一些文本，选中它，然后按 Ctrl-C，这是熟悉的复制操作。现在切换到 esProc，新建一个单元格，在单元格 A1 中输入 =clipboard()，然后执行，看看单元格 A1 的值。

刚才在记事本中复制的文本现在在这里了。clipboard() 函数可以取出复制到系统剪贴板的文本。

然后在 A2 中输入 >clipboard("Hello,esProc")

执行后，切换回记事本，按 Ctrl-V 粘贴。你看到了什么？

带参数的 clipboard() 函数会把作为参数的字符串复制到系统剪贴板，然后可以在其他程序中粘贴。

现在让我们用这个 clipboard() 函数来帮助 Excel 做一些事情。

假设 Excel 中的一列，比如 A 列，有一些名字。例如，前几行如下：

现在我们想知道这些名字中字母 e 被使用了多少次。

Excel 不容易计算这个。让我们用 SPL 来配合。

1) 在 Excel 中选中这一列，按 Ctrl-C 复制到剪贴板。
2) 切换到 esProc，写如下代码：

|   |   |
|---|---|
| =clipboard() |   |
| =A1.split("\n") |   |
| =A2.(~.split()) |   |
| =A3.conj() |   |
| =A4.count(lower(~)=="e") |   |

执行它，A5 就是我们想要的结果。

让我们看看代码执行后脚本中每个单元格的值。A1 如下：

（原文含示意图，图像资源未迁移）

它从剪贴板中取出了刚才在 Excel 中复制的内容。看起来像是把 Excel 列中的文本挤在一起了。看看 A2：

（原文含示意图，图像资源未迁移）

这是一个序列。每个成员正好是 Excel 列中的每一行文本。这是怎么发生的？

实际上，我们从 Excel 复制的是由这些文本组成的一个大字符串，两行之间用回车分隔。回车字符是不可显示的字符，在 esProc 中看不到，所以看起来像是把这些行的文本挤在一起了。A1.split("\n") 表示用回车字符作为分隔符把大字符串拆分成序列，所以它返回到每个成员正好对应 Excel 中每一行的情况。

这里的 "\n" 是回车字符。字符串常量中的反斜杠 \ 叫做**转义字符**。它的作用是帮助我们写一些不方便写的字符。例如，回车用 \n 表示，制表符用 \t 表示。这些是不可显示的字符，但它们也有编码，是两个字符。\n 在字符串中只是一个字符，虽然在引号中写成 \ 和 n（两个字符），\t 也类似。

因为 \ 被当作转义字符，如果我们真的想在字符串常量中有一个 \，它会被转义。要写两次，即 "a\\b" 的实际内容是 a\b，长度是 3；另外，双引号用作字符串的分隔符，但字符串中仍然可能包含双引号。这种情况下，也应该用转义字符来写。"a\"b" 的实际内容是 a"b，长度是 3。

下面的语句很简单。A3 是一个循环函数。它内部的 ~.split() 会把每个成员的字符串拆分成单字符序列，所以 A3 是一个两层序列：
[["J","a","m","e","s"],["A","n","d","r","e","w"],...]

我们在讲递归时遇到过 conj() 函数。它的作用是连接多层序列的成员序列，返回这些成员之间 | 操作的结果。因此，A4 中的 A3.conj() 会得到：
["J","a","m","e","s","A","n","d","r","e","w",...]

lower() 函数把字符转换成小写。现在可以与字符串 "e" 比较，然后计数。

这样写是为了分解步骤，便于解释代码。实际上，这些操作可以连续写：

|   |   |
|---|---|
| =clipboard() |   |
| =A1.split@n().conj() |   |
| =A2.count(lower(~)=="e") |   |

s.split@n(x) 是 s.split("\n").(~.split(x))，因为先按回车拆分再拆分很常见，SPL 给 split 函数添加了 @n 选项。

让我们再看一个例子。

一批电子邮件地址存储在 Excel 的一列中。我们知道，电子邮件地址是 x@y 格式。我们希望对这些电子邮件地址排序，使同一企业的邮箱可以排在一起，即我们希望先按 y 再按 x 的顺序排列，例如 abc@google.com 和 xyz@google.com 应该排在一起，而不是把 abc@google.com 和 abc@apple.com 放在一起，但如果直接在 Excel 中排序会出现后一种情况。

我们仍然使用剪贴板，先在 Excel 中复制这一列数据，然后切换到 esProc 写代码：

|   |   |
|---|---|
| =clipboard() |   |
| =A1.split@n("@") |   |
| =A2.sort([~(2),~(1)]) |   |
| =A3.concat@n("@") |   |
| >clipboard(A4) |   |

执行它，然后切换回 Excel，用 Ctrl-V 粘贴到那一列。它已经按我们想要的方式排列好了。

我们理解了 A1。A2 中的 split@n 先按回车字符把字符串拆分成字符串序列，然后用分隔符 "@" 拆分每个成员。电子邮件地址中有且只有一个 @，所以每个成员字符串会被拆分成两个成员的序列，分别是 @ 前后的部分。然后，用 sort 函数排序时，把序列成员反过来写。这样，根据序列比较规则，会先比较 @ 后面的部分，再比较 @ 前面的部分，即我们想要的顺序。

A4 中的 concat() 是 split() 的相反函数。split() 负责拆分，concat() 负责连接。@n 选项表示对两层序列做 concat。每个成员恢复成原来的电子邮件地址字符串，组装成用回车分隔的大字符串，但现在顺序是合理的。然后用 clipboard() 函数复制到剪贴板。在 Excel 中，只需粘贴即可。

A4 也可以直接写成 A3.sort(~(2),~(1))。sort() 函数也支持多参数形式，表示先比较前面的参数，再比较后面的参数。对于单值序列，多参数 sort() 意义不大，但对于两层序列会更方便。学习了结构化数据后，多参数 sort() 会更常见。

现在我们处理的是 Excel 中的单列数据，多列怎么办？

当然，没问题。

例如，在 Excel 中，我们想把每行的数据从小到大排序。

（原文含示意图，图像资源未迁移）

Excel 通常按行排序，在列方向上排序很困难。用 SPL 很容易实现。在 Excel 中选中并复制这块数据，然后切换到 esProc 执行这样的代码：

|   |   |
|---|---|
| =clipboard() |   |
| =A1.split@n("\t") |   |
| =A2.(~.sort()) |   |
| =A3.concat@n("\t") |   |
| >clipboard(A4) |   |

然后粘贴回去。

从 Excel 复制的这块数据被 clipboard 函数接收后是一个大字符串。每行用回车分隔，即 \n，每行中的列用制表符分隔，即 \t。所以 A2 中的 A1.split@n("\t") 可以把这个大字符串拆分成两层序列，它的内层成员正好是 Excel 中每个单元格的数据；然后在 A3 中对每行排序，在 A4 中连接回这样用 \n 和 \t 分隔的字符串，粘贴到 Excel 中。

仔细看看 Excel 中的结果。好像有点问题。它把 42 排在 5 前面。大小错了吗？

实际上，没有错，因为 split 函数拆分出来的结果仍然是字符串，作为字符串，"42" 比 "5" 小。

那么我们怎么按数值比较呢？我们需要把 A3 改成：
=A2.(~.sort(number(~)))

与 string() 对应，number() 可以把字符串参数转换成数值类型，然后可以按数值规则比较和排序。现在看，没问题了。

在以前的操作系统下，有一个叫 grep 的命令，可以在很多文本文件中找到包含某个字符串的文件和行号。这是一个非常有用的命令，被 Windows 取消了。让我们现在自己实现它。

假设要查找的字符串在 A1 中，让我们指定路径下的所有文本文件：

|   | D |
|---|---|
| Abc |   |
| =directory@p("D:/data/*.txt") |   |
| for B1 |   |
| =file(A2).read@n() |   |
| =filename(A2) |   |
| for B2 |   |
| if pos(B3,A1) |   |
| >output(D2/"\t"/#B3/"\t"/B3) |   |

我们要学习几个新函数。

B1 中的 directory() 函数会返回指定路径下所有 .txt 文件名（最好使用绝对路径，否则可能因为 esProc 的启动路径不确定而找不到文件）。这些文件名会作为字符串序列返回，@p 表示返回的文件名也是完整路径。A2 循环这个序列，B2 读出每个文件，file() 函数用文件名生成文件对象，read@n() 函数把文本文件读成字符串序列，每行一个成员。filename() 取出完整路径文件名中的路径部分。

B3:D3 很容易理解。循环每行文本，如果找到 A1，输出文件名、行号和这行的内容。

这里我们假设文件很小，可以一次读入。如果文件很大，需要使用后面提到的游标技术。

统计一批文章的字数也是常见的练习。学会读文件后，我们也可以练习：

|   |   |
|---|---|
| =directory@p("D:/book/*.txt").sum(file(~).read().words().len()) |   |

不带选项的 read() 函数会把整个文本文件读成一个大字符串，words() 函数会把大字符串中的单词拆解出来形成序列。然后，只需计算长度并加起来。一行就够了。

让我们再做一个在日常工作中可能有用的任务：把一批 Excel 文件合并成一个大文件。

我们可能经常收集各个时期或部门的 Excel 文件。Excel 格式相同。这些文件需要合并成一个完整的文件，以便进一步统计。但手动复制粘贴非常麻烦。如果有几十或几百个文件，会非常累人。这种事情正好让程序来做。

（原文含示意图，图像资源未迁移）

这是非常常见的 Excel 文件格式。

再加一个要求，把原 Excel 文件名拼到合并后 Excel 的最后一列，以便区分数据来自哪个文件。

|   |   |
|---|---|
| =directory@p("D:/data/*.xlsx") |   |
| for A1 |   |

| =filename@n(A2) |   |
| =B2.to(2,).(~|B3) |   |
| =@|B4 |   |
| =if(#A2==1,B2(1)|"File",@) |   |
| =file("D:/all.xlsx").xlsexport@w([B6]|B5) |   |

B3 中的 filename@n() 会拆解出去掉扩展名的文件名部分，也可以通过拆分字符串来做。B2 中的 xlsimport@w() 会把 Excel 文件读成两层序列。Excel 的每行对应一个成员，每行中的每列对应其成员的成员。B4 去掉第一行的标题，把文件名拼到每行末尾。B5 合并这些数据，而 B6 需要保留一个标题并多拼一列。

最后 A7 中的 xlsexport@w() 把汇总的两层序列 [B6]|B5 写入新的 Excel 文件（导出文件时最好使用绝对路径）。

不带 @w 选项的 xlsimport() 实际上可以把 Excel 文件读成更方便的数据类型，完成这个任务的代码会更简单，但要在我们讲完结构化数据后再介绍。

随着深入学习，我们将逐渐进入处理实际任务的阶段。处理文件数据是非常常见的任务。在本节的例子中，我们都使用绝对路径来定位文件。这里简要介绍一下 esProc 使用相对路径时的文件搜索规则（绝对路径可以直接找到）：

如果在环境中设置了主路径（第 6 章第 3 节），esProc 会从这个主路径开始；如果主路径为空，从当前使用的脚本文件所在的路径搜索。当前脚本可能刚创建还没保存。这种情况下，没有路径，所以无法确定在哪里找，很可能找不到。因此，要么设置主路径，要么当前脚本已保存并有路径。

与主路径同时设置的搜索路径用于搜索被调用的脚本，与数据文件无关。把数据文件放在搜索路径中不会使它被自动找到。
