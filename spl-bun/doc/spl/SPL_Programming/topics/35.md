### 7.3 日期和时间

时间相关的处理和计算也很常见。SPL 有三种数据类型：日期、时间和日期时间。

日期数据只有日期信息没有时间信息；时间数据只有时间信息没有对应的日期信息；日期时间既有日期又有时间，相当于某一时刻。

有必要提供一种没有日期信息的时间类型。一些发生在不确定日期的事件没有日期信息，使用时间类型更合适，额外的日期可能会造成混淆。例如，计算 8:00 和 9:00 之间的间隔。如果必须有日期信息，我们必须注意是否是同一天的 8:00 和 9:00，这很容易被忽略。

但是有了更精确的日期时间类型，为什么还要有不精确的日期类型呢？

这类似于整数和浮点数，因为对于很多事件，我们只关心发生的日期，不再关心时间。如果只使用日期时间类型，存储和计算量会变大。而且，比较两个日期是否相等时，还要注意附带的时间信息是否也相等，很容易出错。

不是所有编程语言都提供这三种数据类型，大多数数据库只有日期时间没有日期。

与日期和时间相关的最基本操作是组件的拆分和组合：

|---|---|

| =date(2020,12,2) |   |
| =year(A1) |   |
| =month(A1) |   |
| =day(A1) |   |
| 22:3:5 |   |
| =time(22,3,5) |   |
| =hour(A3) |   |
| =minute(A3) |   |
| =second(A3) |   |
| 2020-12-2 10:3:5 |   |
| =datetime(2020,12,2,10,3,5) |   |
| =datetime(A1,A3) |   |
| =year(A5) |   |
| =month(A5) |   |
| =day(A5) |   |
| =hour(A5) |   |
| =minute(A5) |   |
| =second(A5) |   |
| =date(A5) |   |
| =time(A5) |   |

这些函数非常简单。只要看例子，不需要详细解释。

SPL 还支持把月和年放在一起作为一个组件，即一个六位数。

|   |   |
|---|---|
| ... | ... |
| =date(202012,20) |   |
| =month@y(A9) |   |

有时你会发现这种处理非常方便。

日期时间和字符串之间的转换很麻烦，格式有很多种。例如，2020-12-20 也可能写成 2020/12/20、12/20/2020、20-12-2020，欧美人也可能使用 Dec/20/2020 或 20-Dec-2020 的格式。时间的格式相对较少，但也可能写成 10:03:05 PM 或 22:3:5。

因此，能处理日期和时间的程序语言通常提供格式解析和转换的能力。

|   |   |
|---|---|
| 2020-12-2 | 22:3:5 |
| =string(A1,"yyyy/MM/dd") | =string(B1,"hh:mm:ss") |
| =string(A1,"MM/dd/yyyy") | =string(B1,"HH:m:s") |
| =string(A1,"MMM-d-yy") | =string(B1,"h:m:s a") |
| =string(A1,"d/MMM/yyyy") |   |

这些格式字符串的写法可以在函数帮助中找到。这几乎是全世界通用的规则，这里不详细解释。你只需要知道这种用法。需要强调的是，由于月和分钟的首字母都是 m，需要用大小写来区分。你可以观察 B8。

正如我们前面说的，计算机中只有数字，其他数据类型实际上是通过某种编码方式表示的数字。例如，SPL 中的字符串是用 unicode 编码的，那么日期和时间是怎么编码的呢？

日期和时间数据类型的内部编码是长整数。让我们观察它们的规律：

|   |   |
|---|---|
| 2020-12-1 | 2020-12-2 |
| =long(A1) | =long(B1) |
| =B2-A2 |   |
| 0:0:0 | 0:0:1 |
| =long(A3) | =long(B3) |
| =B4-A4 |   |
| =date(0) | =time(0) |

首先观察 C2，相差 1 天的两个日期，转换成长整数后，差值是 86400000。这个数字是什么？

经常做日期计算的读者会敏感地发现 86400=24*60*60，正好是一天秒数的 1000 倍。观察 C4。相差 1 秒的两个日期，转换成长整数后差值是 1000。这证实了我们的想法，日期和时间对应的长整数是从某一时刻开始的毫秒数。

那么，从哪一时刻开始呢？我们不能通过直接观察 A1、B1、A4 和 B4 来弄清楚，可以简单地反推，观察 A5 和 B5。原来日期是从 1970 年 1 月 1 日开始计算的。这是国际计算机标准组织的约定。1970 年之前的日期应该用负数表示。有趣的是，历史上有几天不是正好 86400 秒，一个日期对应的长整数值并不总是从 1970 年 1 月 1 日开始的天数乘以 86400000。有兴趣的读者可以编程找出是哪几天（用我们到目前为止学到的技能，读者应该能做到），然后在网上搜索为什么这些日期不是 86400 秒。

让我们看看时间，B5 的结果很奇怪。我在这里计算出来是 8 点。为什么不是从 0 点开始？

因为我在中国北京写这本书。北京的时区是东八区，北京时间 8:00 正好是格林威治标准时间 0:00。时间是从 0:00 开始计算的，但是是格林威治标准时间，不是当地时区。如果你现在恰好在英国，计算出的 B5 会是 0。

日期和时间有这么多有趣的事情。

让我们继续学习日期和时间操作。最常见的需求是计算两个时刻之间的间隔，以及从某一时刻经过一段时间后的时间。

例如，如果我们想看看计算水仙花数时使用的优化方法有多有效，我们需要计算这个程序的执行时间：

|   | D | E | F |
|---|---|---|---|
| =now() |   |   |   |
| for 1000 |   |   |   |
| =0 | =[] |   |   |
| for 9 |   |   |   |
| =100*B3 | =B3*B3*B3 |   |   |
| for 0,9 |   |   |   |
| =C3+10*B4 | =D3+C4*C4*C4 |   |   |
| for 0,9 |   |   |   |
| =D4+D5 | =E4+D5*D5*D5 |   |   |
| if E5==E5 |   |   |   |
| >C2.insert(0,E5) |   |   |   |
| =now() |   |   |   |
| =interval@ms(A1,A7) |   |   |   |

这里我们需要使用生成结果序列的代码，因为 output 方法会涉及屏幕显示。实际上，这个动作非常复杂，可能比完成这些计算花费更长的时间，而且不是计算时间的测试。而且，我们重复了这个动作 1000 次，因为现代计算机的 CPU 太快了，只执行一次看不出差别。

A1 的 now() 会返回执行这条语句时的时间，即在 A1 中记录程序的开始时间。在 A7，用 now() 获取程序结束的时间，然后用 interval@ms() 计算两个时刻之间的间隔，按时间顺序写两个参数，从而得到程序的执行时间。

now() 返回日期时间类型，可以精确到毫秒。interval() 的 @ms 选项表示计算的时间间隔精确到毫秒。因为程序执行非常快，即使重复 1000 次，如果不精确到毫秒，我们仍然看不出差别。

现在对优化后的代码做同样的改造并执行：

|   | D | E | F | G |
|---|---|---|---|---|
| =now() |   |   |   |   |
| for 1000 |   |   |   |   |
| =0 | =[] |   |   |   |
| for 9 |   |   |   |   |
| =100*B3 | =B3*B3*B3 |   |   |   |
| for 0,9 |   |   |   |   |
| =C3+10*B4 | =D3+C4*C4*C4 | break |   |   |
| for 0,9 |   |   |   |   |
| =D4+D5 | =E4+D5*D5*D5 |   |   |   |
| if E5==E5 |   |   |   |   |
| >C2.insert(0,E5) |   |   |   |   |
| else if E5<F5 |   |   |   |   |
| break |   |   |   |   |
| =now() |   |   |   |   |
| =interval@ms(A1,A8) |   |   |   |   |

比较这两个时间间隔，我们可以知道优化是否有效。在我的电脑上，优化后的代码快了大约 25%，这是相当明显的。

interval() 函数有各种选项，可以返回不同精度的时间间隔。在日常工作中，最常见的任务是计算两个日期之间的天数，这也是不使用选项时 interval() 函数的默认返回值。而且，因为太常见了，SPL 简化了这个计算，可以直接用减法表示，即 interval(d1,d2)==d2-d1。

某人在 2018 年 12 月 4 日借了 25000 元，日利率 0.013%。如果他今天还，应该付多少利息？

|   |   |
|---|---|
| =25000*0.013/100*interval(date(2018,12,4),now()) |   |
| =25000*0.013/100*(now()-date(2018,12,4)) |   |

A1 和 A2 的结果相同。now() 包含日期信息，可以用作今天。

让我们把案例稍微复杂一点。如果每年年底把利息加到本金上，以后的利息按此计算，今天还的话总共应该付多少？

换句话说，每年 1 月 1 日，计算当时的利息并加到本金上，以后的利息按此计算。我们用一种笨方法来计算，从借款日期到今天逐日循环。

|   | D |
|---|---|
| 2018-12-4 | 0.013% |
| =25000 | =0 |
| for now()-A1 |   |
| if month(A1)==1 && day(A1)==1 |   |
| >C1+=D1 |   |
| >D1=0 |   |
| >A1=elapse(A1,1) |   |
| >D1+=B1*C1 |   |
| =C1+D1 |   |

当前利息存储在 D1 中。初始值是 0。循环的每一天，利息会增加一天。如果当前日期是 1 月 1 日，把当前利息加到本金上，然后清零利息。循环结束时，把当时的本金和利息相加。

需要注意的是，在单元格 B3 中，elapse(d,n) 函数返回日期 d 之后 n 天的日期，有了这个动作，循环才能正常运行。

像 interval() 一样，elapse() 有很多选项来控制精度。而且，当精度是天时，可以直接用加法表示。即单元格 B3 可以简单地写成 >A1=A1+1，甚至 >A1+=1。

百分比常量可以在单元格中直接用 % 表示，但在表达式中不行，% 会被当作取余运算符。
