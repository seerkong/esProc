### 8.2 序表和记录序列

有了结构化数据的基本概念，让我们学习如何处理这些数据，也就是前言中提到的本书的后半部分。

在用于处理结构化数据的编程语言中，SQL 是目前使用最广泛的。SQL 的全称是结构化查询语言，意思是专门用于结构化数据查询的语言。它是关系数据库的通用语言。

除了 SQL 相关资料外，大多数编程书籍不讲结构化数据。讲完相当于本书前半部分的内容后，就开始转向更高级的面向对象内容。对于非专业人士来说，这本书可以说已经结束了。然而，学到这个程度，除了做一些中小学的数学题（就像上面提到的例子）来锻炼我们的大脑外，对我们的日常工作不会有任何实质性的帮助。只有学习了结构化数据的知识和技能，才能真正用编程来提高工作效率，这也是本书的重要目标。

然而，本书不打算讲 SQL。这方面的资料很多。如果读者有兴趣，可以自学。SQL 通常只能在数据库中使用，而安装和管理数据库的技能要求有点高，不适合本书的读者。

我们继续使用 SPL。与 SQL 相比，SPL 有更丰富的结构化数据处理能力。在大多数情况下，代码比 SQL 更简洁，而且环境不依赖数据库，更适合非专业人士。

实际上，SPL 的全称是结构化过程语言，也是为处理结构化数据而发明的。结构化数据非常常见。日常工作中的大多数数据处理任务都与结构化数据有关，有必要发明一种更高效的程序语言。

实际上，esProc 中允许对文件数据使用 SQL。基本的 SQL 功能作为 SPL 的特殊语句实现。你也可以用 esProc 学习 SQL，而不需要安装数据库。

回到正题，让我们先看看如何创建数据表。

|   |   |
|---|---|
| =create(name,sex,weight,height) |   |

create() 函数创建一个空数据表。数据表必须有数据结构，即字段名，依次填入 create() 函数的参数中。新创建的数据表没有记录。查看数据时，我们会看到右边只有一个表头。

让我们把代码写得更完整，添加一些数据。

|   | D |
|---|---|
| Zhang San | Male | 70 | 1.75 |
| Li Si | Male | 60 | 1.68 |
| Wang Hua | Female | 50 | 1.64 |
| Zhao Ting | Female | 45 | 1.6 |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |

在 A5 中创建数据表，然后在 C5 中使用 record() 函数填入数据。我们之前讲过 [A1:D4] 的写法。record() 函数用于把序列（参数）的成员作为字段值填入数据表。序列成员会按照数据结构中的字段顺序填入。填完一条记录后，如果还有剩余的序列成员，会为数据表创建新记录继续填入剩余的序列成员。

现在查看数据（record 函数仍然返回数据表。查看 A5 或 C5 是一样的）。

（原文含示意图，图像资源未迁移）

这看起来与序列值非常相似，只是序列显示为一列，而数据表显示为多列，每列有一个名称（字段名）。esProc 还会自动在左边显示一个索引列，方便计数。看起来像是一个更复杂的序列？

我们确实可以把 SPL 中的数据表理解为以记录为成员的序列（还是有点不同，稍后再讲）。实际上，SPL 中数据表的正式名称是**序表**，因为 SPL 非常强调表中记录的顺序。对于习惯 Excel 的人来说，记录（即行）有顺序是自然的；但对于数据库程序员来说，数据表中的记录是无序的。SPL 强调顺序是为了与 SQL 区分。

数据表叫序表，但记录仍然是记录，字段也是字段。

既然序表是由记录组成的序列，能不能通过引用序列中的成员来获取记录呢？

可以，我们可以继续写代码：

|   | D |
|---|---|
| ... | ... |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| =A5(1) | =A5(3) | =A5.m(-1) | =A5.len() |

看看执行后 A6 的值：

（原文含示意图，图像资源未迁移）

仍然显示为带表头的表格，但只有一行数据，左边没有索引列。

这是一条记录。它有数据结构（即序表的数据结构），即字段。它的每个字段都有一个值，列在上面。

A5 确实像一个序列。它可以正确执行 A5.m(-1) 这样的代码，A5.len() 也可以。

让我们研究一下记录。能不能获取记录的字段值来参与运算？继续写：

|   | D |
|---|---|
| ... | ... |
| =A5(1) | =A5(3) | =A5.m(-1) |   |
| =A6.weight/A6.height*A6.height |   |
| >output(if(B6.height>C6.height,B6.name,C6.name)+" is taller") |   |

用 . 运算符后跟字段名来获取字段值。A7 中计算了第一个人张三的 BMI，A8 中比较了第三和第四个人的身高，并显示较高者的名字。

能不能改变字段值？也可以。

|   | D |
|---|---|
| ... | ... |
| =A5(1) | =A5(3) | =A5.m(-1) |   |
| =A6.weight/A6.height*A6.height |   |
| >output(if(B6.height>C6.height,B6.name,C6.name)+" is taller") |   |
| =C6.height=1.8 |   |
| =A5(4).name="NewZhaoTing" |   |
| >output(if(B6.height>C6.height,B6.name,C6.name)+" is taller") |   |

可以使用提取的记录变量（C6）和直接的序表成员（A5(4)）来引用和修改字段值。

对于记录 r 的字段 F，r.F 相当于一个名称稍微复杂的变量，可以在表达式中自由引用或赋值。

我们可以看到，在 SPL 中，我们可以从序表中获取一条记录来单独查看和计算。不要认为这是理所当然的。这在 SQL 中是不允许的。SQL 记录不能在数据表外独立计算。

回顾我们之前讲的对象概念。复杂数据类型不是直接存储在变量中，而只是一个地址。记录有多个字段，看起来有点复杂。是一样的吗？

|   | D |
|---|---|
| ... | ... |
| =A5(1) |   |
| =A6 |   |
| =A5(1) |   |
| >A6.name="Test" |   |
| =B6.name |   |
| =C6.name |   |

做一些实验就知道了。记录也是一个对象。不仅记录变量中存储的是记录的地址，序表中也是，不会复制记录值。修改记录的字段值会影响所有后续引用这个记录字段的代码。

至于序表，它显然是一个对象。

而且，记录有更特殊的特性：

|   | D |
|---|---|
| Zhang San | Male | 70 | 1.75 |
| Li Si | Male | 60 | 1.68 |
| Wang Hua | Female | 50 | 1.64 |
| Li Si | Male | 60 | 1.68 |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| =A5(1)>A5(2) | =A5(2)==A5(4) | =A5(2)>A5(4) |   |

我们故意把第 4 行和第 2 行的数据填成完全一样，然后观察第 6 行三个逻辑表达式的计算结果。

A6 和 C6 的结果是不可预测的，多次执行可能得到不同的结果。B6 总是 false。

这是怎么回事？

记录的字段不像序列的成员那样总是同类事物。用字段顺序来比较两条记录通常没有意义。例如，这里 name 字段在 sex 前面，但没有理由说 name 在比较中应该优先于 sex。然而，也没必要返回错误，所以 SPL 规定用内部地址值来比较记录，所以 A6 和 C6 会得到不可预测的结果。至于同一序表的两条记录，即使内容完全相同，也会分别分配内存空间，它们的地址值也不同，所以两条不同的记录永远不会相等。

那么，如果我们只想比较两条记录的字段值是否相等，或者只想按字段顺序比较记录，该怎么办呢？

SPL 提供了专门的函数来做这种比较：

|   | D |
|---|---|
| Zhang San | Male | 70 | 1.75 |
| Li Si | Male | 60 | 1.68 |
| Wang Hua | Female | 50 | 1.64 |
| Li Si | Male | 60 | 1.68 |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| =cmp(A5(1),A5(2)) | =cmp(A5(2),A5(4)) |   |   |

现在我们会得到确定的结果。不同的是，cmp() 函数不返回 true 或 false，而是返回一个整数。如果相等，返回 0；如果前者较小，返回 -1；如果前者较大，返回 +1。比较有三种情况。

为什么 SPL 不直接规定记录的比较就是 cmp() 函数的计算结果呢？

按 cmp() 函数的规则比较记录不是常见操作。麻烦一点也没关系。比较记录变量中存储的地址是否相同（以确定是否是物理上相同的记录）是相对常见的操作，经常隐式执行（如后面要讨论的分组操作）。如果规定记录比较就是 cmp() 操作的结果，比较地址的动作会麻烦得多或效率低下。因此，SPL 当前规则的约定是权衡计算效率和代码复杂性的结果。

序表像是由记录组成的序列。能不能像序列一样用 insert() 和 delete() 函数来添加和删除成员呢？

delete() 可以，但 insert() 不同。这是序列和序表的关键区别。

正如我们所说，数据表只有一套数据结构。向序表添加记录时，必须是具有相同数据结构的记录。如果允许随便抓一条记录插入序表，我们需要详细检查以避免这种情况。而且，这可能导致一条记录属于两个不同的序表。当一个序表因某种原因调整数据结构时，可能导致另一个序表中数据结构的不一致。这太麻烦了，严重影响程序的效率。

因此，SPL 规定记录必须从序表生成，不能插入其他序表。这样，序表的记录都在序表的控制之下。不会有来自另一个序表的记录，也不会有来自其他地方的记录。因此，我们会发现 SPL 提供了创建序表的函数，但没有创建单独记录的函数。记录创建后，可以在序表外参与其他操作，但创建时必须附属于一个序表。创建的单条记录本质上是只有一条记录的序表中的记录。这个序表可以继续插入新记录。

这也可以解释上面的：不同的记录永远不会相等。

序表的 insert() 函数是这样做的：

|   | D |
|---|---|
| ... | ... |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| >A5.insert(0,"Mary","Female",55,1.7) |   |
| >A5.insert(2,"John","Male",75,1.8) |   |

insert() 的第一个位置参数与序列 insert 的含义相同。记录可以插入中间或追加到末尾。然后在剩余参数中写入要插入记录的每个字段值。SPL 会在序表的适当位置创建新记录并填入字段值。

把成员组装成序列，即集合，是为了方便一起操作和处理，例如我们可以使用上面提到的循环函数。如果序表的记录必须存在于序表中，不同序表的记录能不能放在一起操作呢？而且，即使是同一个序表，也不一定所有成员都一次参与操作，序列有获取子序列的方法。这对序表还有效吗？

这些操作在 SPL 中是允许的。记录只在创建时附属于序表，以确保其数据结构的一致性。一旦创建，就可以像普通数据一样自由引用和组合。

由来自不同序表的一批记录组成的序列，或由序表的部分记录组成的序列，非常常见。这种序列在 SPL 中有一个特殊的名称，叫做**记录序列**。

当然，记录序列也是一个对象。

关于序表和记录序列的循环函数，我们稍后再讲。现在我们手动创建几个记录序列：

|   | D |
|---|---|
| ... | ... |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| =A5.to(2,) | =[A6(1),A5(4),A5.m(-1)] | =A5.step(2,2) |   |
| =A6.len() | =B6(2)==B6(3) | =C6(1)==A6(1) |   |

目前，我们手头只有一个序表，只能创建由这个序表的记录组成的记录序列。注意 B6，记录序列的成员可以从另一个记录序列引用，不一定直接从序表引用。而且，它的成员可以重复，B7 会计算出 true；序表的成员不能彼此相等，因为每次都是新创建的；而不同的记录序列当然可以由相同的记录组成，C7 也计算出 true。

记录序列可以理解为普通序列，因为它可能有相同的成员，集合操作也是有意义的：

|   | D |
|---|---|
| ... | ... |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| =A5.to(2,) | =[A6(1),A5(4),A5.m(-1)] | =A5.step(2,2) |   |
| =A6&B6 | =A6^C6 | =A5\C6 |   |

这些集合操作的结果仍然是记录序列，序表本身可以看作是由其所有记录组成的记录序列，也可以参与这些集合操作，但计算结果将不再是序表，而只是记录序列。

现在让我们再做一次合并 Excel 的问题，由于我们还没学会改变数据结构，我们减少一个要求：只合并数据，不在末尾添加文件名。

|   |   |
|---|---|
| =directory@p("data/*.xlsx") |   |
| for A1 |   |
| =file(A2).xlsimport@t() |   |
| =@|B2 |   |
| =file("all.xlsx").xlsexport@t(B3) |   |

我们已经理解了 A1。这次，B2 使用不带 @w 的 xlsimport() 函数，它会把文件读成序表，@t 表示文件的第一行是序表的字段名。循环体中的 B3 连接每次读取的序表，这会形成一个由来自多个序表的记录组成的序列，即由来自多个序表的记录组成的记录序列。连接后，只需在 A4 中用 xlsexport() 函数写入，@t 也表示把字段名写到第一行作为标题。

这段代码比之前的字符串处理简单得多，不需要处理标题的拆解和组装。实际上，使用循环函数可以更简单：

|   |   |
|---|---|
| =directory@p("data/*.xlsx").(file(~).xlsimport@t()).conj() |   |
| >file("all.xlsx").xlsexport@t(A1) |   |

多个记录序列也可以形成两层序列，然后用 conj() 函数连接成一个。

这段代码要求合并的 Excel 文件有相同的数据结构（即相同的列）。实际上，记录序列不要求所有成员记录有相同的数据结构。只要引用字段时不出错就没问题。然而，这种情况非常罕见，我们不举例了。
