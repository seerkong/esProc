### 8.3 序表的生成

为了进一步学习记录序列的操作，我们需要一个记录多一点的序表，比如我们之前用过的有四个字段的序表：name、sex、weight、height。生成几百条记录再做实验会方便得多。

显然，手动填写很多记录的字段值太麻烦了。我们用程序来生成。字段的具体值不影响学习。可以随机生成。

用我们现在学到的代码技术已经可以做到这一点。

|   |   |
|---|---|
| =create(name,sex,weight,height) |   |
| for 100 |   |
| =string(A2) | =if(rand()<0.5,"Male","Female") |
| =50+rand(50) | =1.5+rand(40)/100 |
| >A1.insert(0,B2,C2,B3,C3) |   |
| =A1.len() |   |

有意义的名字很麻烦，所以我们用数字字符串代替。C2、B3、C3 很容易理解，然后在 B4 中，把生成的字段插入 A1 中创建的空序表。代码执行后，我们可以得到一个有 100 条记录的序表。

这段代码没问题，但还是有点麻烦。我们学过循环函数，很容易想到应该有一个循环函数来解决这个任务。然而，用于生成新序列的循环函数 100.(x) 只能返回序列，这不是我们需要的。

SPL 提供了一个循环函数来返回新序表。上面的代码可以简化成一条语句：

|   |   |
|---|---|
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |   |

有点长，所以写成两行。与结构化数据相关的语句往往很长。这也是用单元格写代码的优点。不会让单元格中太长的代码写出单元格，影响右边和下面的代码阅读。

类似于 A.(x) 返回与 A 长度相同的序列，A.new(...) 会返回记录数与 A.len() 相同的序表。它也为 A 的每个成员生成一条记录，这些记录会形成序表并返回。

new() 函数的参数写法有点不同。

很明显，每个字段用逗号分隔。字段值的计算公式在冒号前面，字段名在冒号后面。这个冒号是 new() 函数的特殊规定吗？

是，也不是。

处理结构化数据后，我们经常面对更复杂的函数参数。例如，要正确执行 new() 函数，我们需要知道要生成的序表中每个字段的值计算公式和字段名，而且字段值计算公式和字段名是一对，不能错位。用当前的 new() 函数，字段值公式和字段名总是两个一组。如果我们仍然使用逗号分隔的写法，仍然可以用参数的位置来确定对应关系，但已经看起来很晕了。如果每组的参数数量不确定，就根本没办法对应了。实际上，new() 函数确实允许省略字段名。在很多情况下，它可以自动识别合理的字段名。如果每次都要写字段名，会非常麻烦。

这种情况下，一种方法是用集合作为参数。例如，这个 new 函数可以写成：
=100.new({string(~),name},{if(rand()<0.5,"Male","Female"),sex},{50+rand(50),weight},{1.5+rand(40)/100,height})

这里的参数分成四组。每个字段是一组，每组有两个成员，即计算公式和字段名。这样，参数之间的对应关系可以描述清楚。如果不写字段名，结果是一组只有一个成员，不会与其他组的参数错位。

这就是**多层参数**的概念。函数中写的参数应该分成多层组，以确保清楚描述这些参数之间的对应关系。

理论上，可能有更多层，所以 {} 可能嵌套，这看起来还是有点乱。

SPL 没有采用嵌套 {} 的写法，而是约定只支持三层参数，分别用分号、逗号和冒号分隔。分号是第一层。分号分隔的参数是一组。如果这组中有下一层参数，用逗号分隔，再下一层参数用冒号分隔。总共三层。

实践表明，三层基本够用，很少有用这种方法描述不清楚的参数关系。而只用逗号往往是模糊的。

实际上，我们在讲 top() 函数时见过分号，但没有仔细分析。

多层参数语法也是 SPL 的发明。它不是只为结构化数据计算设计的。在常规数值运算中也会涉及，但由于结构化数据处理的复杂性，经常出现。

如果你学过 SQL，可以比较一下。SQL 中用关键字分隔的每个部分也可以理解为多层参数。只是假装是英语会有更好的可读性，但通用性差得多。你应该为每个语句选择特殊的关键字。结构化数据的复杂性会迫使多层参数出现（以不同的形式）。

理解了多层参数后，上面的 new() 函数就容易理解了。冒号确实是 new() 函数参数所需要的，因为它有两层参数，但不是专门为 new() 函数规定的，而是 SPL 中的通用规则。

序表的 insert() 函数也有多层参数。插入时可以指定字段名。参数中未列出的字段插入后会填入 null。

例如，我们需要把刚才用 new 函数创建的 100 条记录添加到之前有 4 条手动记录的序表中，但只填入 weight 和 height，让其他的为 null。

|   | D |
|---|---|
| ... | ... |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| for 100 |   |
| >A5.insert(0,50+rand(50):weight,1.5+rand(40)/100:height) |   |

在实践中，结构化数据往往有很多字段，如果不允许默认写法会更麻烦。

类似于序列，序表的 insert() 也可以一次批量插入多条记录：

|   | D |
|---|---|
| ... | ... |
| =create(name,sex,weight,height) |   |
| =A5.record([A1:D4]) |   |
| >A5.insert(0:100,50+rand(50):weight,1.5+rand(40)/100:height) |   |

多层参数可以很容易地用一种模式表达各种意图。

现在我们有一个 100 条记录的序表，每条记录对应一个人。我们想得到一个新序表，多一个字段来存储每个人的 BMI。

用 new() 函数，很容易：

|   |   |
|---|---|
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |   |
| =A1.new(~.name:name,~.sex:sex,~.weight:weight,~.height:height,~.weight/~.height/~.height:bmi) |   |

作为循环函数，A1.new() 中的 ~ 定义为序列循环时的当前成员，即序表 A1 的一条记录。然后我们可以用 ~.F 的语法来引用记录 ~ 的字段。

然而，这样写的 A2 有点长。

SPL 规定，在序表或记录序列的循环函数中，可以直接用字段名来引用当前成员的字段，不用写 ~.，即 name 就是 ~.name，sex 就是 ~.sex，……而且，正如我们前面说的，new() 函数有时可以省略字段名，当当前公式和目标序表的字段名相同时可以省略。这样，A2 可以写成：

|   |   |
|---|---|
| ... |   |
| =A1.new(name,sex,weight,height,weight/height/height:bmi) |   |

这样看起来清晰多了，也不容易出错。

这种在末尾追加字段的情况在结构化数据处理中非常常见。SPL 干脆提供了一个函数来处理，代码可以简化为：

|   |   |
|---|---|
| ... |   |
| =A1.derive(weight/height/height:bmi) |   |

derive() 函数会在原序表的数据结构基础上追加新字段，原序表的所有字段都会被复制。

需要注意的是，derive() 函数会创建新序表，不会改变原序表。它会复制原序表的所有字段和值，原序表仍然在那里。实际上，derive() 函数可以对记录序列执行，不一定是序表。

new() 函数当然会创建新的，它甚至可以对序列执行，而不是记录序列。

现在，我们可以把合并 Excel 的问题恢复到之前的要求：在末尾追加文件名。

|   |   |
|---|---|
| =directory@p("data/*.xlsx") |   |
| =A1.(file(~).xlsimport@t().derive(filename@n(A1.~):File)) |   |
| >file("all.xlsx").xlsexport@t(A2.conj()) |   |

语句有点长，我们多写了一行。实际上所有动作可以写在一条语句中。

对于每个文件读出的序表，用 derive() 函数在末尾追加一个 File 字段，值是当前文件名。需要注意的是，derive() 是一个循环函数，直接写在其表达式中的 ~ 指的是序表（记录序列）的当前记录。这里，添加文件名时，我们应该使用上层的 ~，即 A1.~。
