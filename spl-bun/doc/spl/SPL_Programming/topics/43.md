## 提取内容

### 9.1 分组和聚合

当事物很多时，人们习惯于根据属性把这些事物分成几类，然后研究每类的一些汇总信息。这种操作在结构化数据上叫做**分组**。分组的具体动作是：根据某个字段把数据表中的记录分成几个小集合，字段值相同的分到同一个小集合，这个小集合叫做**分组子集**或**组**，然后计算每组记录的一些统计值来研究这些数据的规律。

例如，在之前生成的人员表中，我们可以按性别计算平均身高和最大体重。

|   |   |
|---|---|
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |   |
| =A1.groups(sex;avg(height):avg_height,max(weight):max_height) |   |

groups() 函数可以实现上述动作。这里也使用了多层参数。分号前面是用于分组的字段，这里是 sex；分号后面是要做的聚合操作。这里有两个，平均身高和最大体重，用逗号分隔。

groups() 函数的返回值是一个序表，以用于分组的字段和聚合表达式作为数据结构；因为返回的是序表，需要设置字段名。在 groups() 函数的每个参数后面写上，用冒号分隔。对于要分组的记录序列，返回序表的记录数取决于分组字段的值的数量，它们是完全一样的。

（因为数据是随机生成的，统计值每次都会变化，而且不符合常识。但不影响理解。）

groups 函数后半部分的聚合操作不能随便写。它只能支持预先做好的几个聚合函数。常见的聚合操作有五种：sum、count、avg、max 和 min。在参数中写这些操作相当于对这些子集（也是记录序列）执行聚合函数。

聚合也可以对表达式进行，比如：

|   |   |
|---|---|
| ... |   |
| =A1.groups(sex;min(weight/height/height):min_bmi) |   |

不一定要按字段分组，也可以按字段计算出的结果分组。

|   |   |
|---|---|
| =100.new(date(now())-100+~:dt,rand()*100:price) |   |
| =A1.select(day@w(dt)>1 && day@w(dt)<7) |   |
| =A2.groups(day@w(dt)-1:wday;min(price):min_p,max(price):max_p) |   |

对股票数据进行分组聚合，计算所有周一、周二、...、周五的最高和最低股价。计算结果是 5 条记录（周末已被排除）。

对于分组字段或表达式，我们有一个术语叫**分组键**。学了后面的内容我们就会理解为什么用"键"这个词。

分组键也可以有多个：

|   |   |
|---|---|
| =1000.new(date(now())-1000+~:dt,rand()*100:price) |   |
| =A1.select(day@w(dt)>1 && day@w(dt)<7) |   |
| =A2.groups(month(dt):m,day@w(dt)-1:wd;avg(price):price) |   |

A3 可以计算每个月每个工作日的平均股价。当有多个分组表达式时，数据表会被分得更细，组数大致等于这些分组键的值类型数量的乘积。例如，上面的操作会分成 12*5=60 组，因为月份有 12 种，工作日有 5 种（不包括周末）。返回的序表有 60 条记录。

（原文含示意图，图像资源未迁移）

然而，这不是绝对的。因为在这组数据中，任何月份的任何工作日都有数据，这 60 组都会有对应的聚合数据。有时数据不完整，有些组就不再存在。例如，我们在 A2 中做一个抽样，随机取 100 条记录然后观察分组结果（我们之前学过如何抽样），看看返回的序表是否总是有 60 条记录。请自己试试。

因为可能有多个分组键，groups 函数在参数中使用更高级的分号来分隔用于分组键的表达式和用于聚合的表达式。这里你可以体会多层参数的便利。

实际上，分组聚合也可以完全没有分组键。

|   |   |
|---|---|
| ... |   |
| =A1.groups(;min(weight/height/height):min_bmi) |   |

这意味着所有成员分到一个集合，即不拆分。对这整个集合，计算一些聚合值，返回的序表只有一条记录。

然而，这种操作不常见，因为可以直接用聚合函数做。

类似地，分组聚合也可以没有聚合值部分：

|   |   |
|---|---|
| ... |   |
| ... |   |
| =A2.groups(month(dt):m,day@w(dt)-1:wd) |   |

A3 会计算这些股票交易发生的月份和工作日（我们可以用刚才提到的抽样减少数据量来试试结果），即我们只关心能分出哪些组，不关心每组的聚合值。

这是一个常见操作。它会计算数据表中分组键的可能值，列出所有可能的值而不重复。数据库行业对这个操作有一个专门的名称，叫做获取 **DISTINCT** 值。

SPL 也提供了一个 id() 函数来计算 DISTINCT。

|   |   |
|---|---|
| ... |   |
| ... |   |
| =A2.groups(month(dt):m) |   |
| =A2.id(month(dt)) |   |

与返回序表的 groups() 函数不同，id() 返回一个没有数据结构、没有字段名参数的序列。

带多个参数的 id() 函数不是计算多个分组键的 DISTINCT，而是分别计算多组 DISTINCT 值。如果我们想计算多个分组键组合的 DISTINCT 值，需要使用序列表达式。

|   |   |
|---|---|
| ... |   |
| ... |   |
| =A2.groups(month(dt):m,day@w(dt)-1:wd) |   |
| =A2.id(month(dt),day@w(dt)-1) |   |
| =A2.id([month(dt),day@w(dt)-1]) |   |

你可以观察 A3、A4 和 A5 的返回结果，特别是这些返回值的长度（作为序表或序列）。

同样，通过抽样数据然后执行这些代码更容易看出差别。

|---|---|

| =A1.id(Company) |   |

DISTINCT 让我们知道有些分组不需要汇总。实际上，有些分组不应该汇总。

例如，在一群人中，我们想知道谁和别人有相同的生日。很简单，按生日分组后，只要看哪些组有多于一个成员。然而，groups() 函数会强制做汇总动作，我们会丢失那些分出来的组。

分组并不总是强制汇总。有时我们也对分组后的子集感兴趣。实际上，分组这个词在字典里只有拆分的意思，并不继续汇总。因为这个操作是 SQL 发明的，而 SQL 的集合数据类型比较弱，无法维护分组的中间结果，所以强制做了汇总。久而久之，整个行业都觉得分组必须伴随汇总，忘记了分组的本意。

SPL 恢复了这个操作。不带 s 的 group() 函数只分组不汇总。groups() 函数名中的 s 表示汇总（summary）。

|   |   |
|---|---|
| =200.new(string(~):ID, date(now())-10000+rand(3000):Birthday) |   |
| =A1.group(month(Birthday),day(Birthday)) |   |
| =A2.select(~.len()>1).conj() |   |

随机生成 200 人的生日，然后按生日分组（不算年份）。group() 函数返回分出来的组，即由一些记录序列组成的序列，相当于两层序列。然后，只需看哪个组有多于一个成员，这是我们学过的语法。最后，把这些组连接起来。

不汇总的分组有实际的业务意义。找同生日的人只是一个游戏。让我们再举一个实际的例子，对于之前的 Excel 文件，我们想按 Area 字段把它拆分成多个文件，给不同的经理处理。

用分组操作来拆分是合理的，但显然我们不能再汇总了。

|   |   |
|---|---|
| =T("data.xlsx") |   |
| =A1.group(Area) |   |
| for B1 |   |
| >T(A2.Area/".xlsx",A2) |   |

T() 函数也可以直接把记录序列写入 Excel 文件。按 Area 分组后，把每组写入对应的文件。A2.Area 是 A2(1).Area 的缩写。根据 SPL 的约定，从记录序列获取字段相当于从它的第一个成员获取字段。

有时，即使我们想得到分组子集的聚合结果，也不容易计算，没有简单的聚合函数可用。这种情况下，我们也需要保留分组子集以便进一步计算。

例如，我们想按性别对人员表分组，把同性别人的名字（现在是一些数字字符串）连接成一个逗号分隔的字符串。这确实是一个聚合结果，但 SPL 没有这样的聚合函数，可以用表达式来写：

|   |   |
|---|---|
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |   |
| =A1.group(sex).new(~.sex,~.(name).concat@c():Names) |   |

只需对分组后的子集序列做 new()。

这种操作很常见。SPL 也允许把它简化到 group() 函数的参数中：

|   |   |
|---|---|
| ... |   |
| =A1.group(sex;~.(name).concat@c():Names) |   |

注意这很容易与 groups() 混淆。group() 分号后面的计算相当于简化的 new()，我们需要写 ~ 来表示分组子集。但在 groups() 中不需要写 ~。实际上，它的计算方法不同。它不是先计算子集再计算汇总值。

如前所述，常见的聚合操作有五种。SPL 还提供了其他可以在分组聚合中使用的聚合函数，但大多数不需要特别提及。需要时可以查文档。这里只提一个 icount()。

icount(x) 返回每组中 x 的 DISTINCT 值的数量。这大致相当于在组内再做一次分组，但内层分组只计数，不做其他汇总。

例如，我们想计算每个地区有多少家公司有业务往来：

|   |   |
|---|---|
| =T("data.xlsx") |   |
| =A1.groups(Area;icount(Company)) |   |

如果你理解了之前提到的迭代函数，SPL 也允许你拼出新的分组和汇总操作。而且，充分理解迭代函数后，你也会意识到 groups() 和 group() 在计算汇总值时使用不同的方法。groups() 使用迭代函数方法计算汇总值，过程中不会维护每个分组子集，这样会更高效、使用更少内存。这也是单独设计 groups() 的主要原因（它的语法有时比 group() 稍微简单，但这只是次要原因）。

另外，分组操作不仅对结构化数据有效，对数值或字符串序列也有效。

|   |   |
|---|---|
| =100.(rand(100)).groups(~%2;sum(~)) |   |
| =directory("*.*").group(filename@e(~)) |   |

A1 会按奇偶性对整数分组并计算每组的和；A2 按扩展名把路径下的文件名分成几组。

然而，对序列的分组相对不常见，所以我们在结构化数据部分讲这个操作。
