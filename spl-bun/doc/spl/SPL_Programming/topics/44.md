### 9.2 枚举和对齐

分组键相等的成员分到一组，这叫做**等值分组**。等值分组满足以下两个特点：
1) 原集合的所有成员都在且只在唯一的一组中
2) 没有空组

满足这些特点的分组在数学上也叫做完全划分。

那么有没有不完全划分呢？

有的，完全划分的两个要求可能不满足。例如，结果中可能有空子集，或者原集合的某些成员可能不在任何组中或在多个组中。

本节我们讲这种分组。

我们做过按性别对人员表分组统计。一般来说，我们期望返回的序表有两条记录，即男一条女一条，甚至确保顺序，这样我们就能确切知道用哪条记录来获取男或女的汇总结果。

然而，等值分组不能保证这个结果。

因为这个人员表中不一定有两种性别。如果只有一种性别，返回的序表只有一条记录。这种情况下，我们必须再比较一下才能知道这条记录是男还是女。

这很不方便。我们想确保返回两条记录，顺序也是确定的。如果要分组的数据中只有一种性别，让另一种性别的汇总值为 0。

这种分组叫做**对齐分组**。它不是完全划分，因为可能出现空集。

|   |   |
|---|---|
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |   |
| [Male,Female] |   |
| =A1.align@a(A2,sex) |   |
| =A3.new(A2(#):sex,~.avg(height):avg_height,~.max(weight):max_height) |   |

对齐分组之前，需要有一个基准序列，比如这里的 A2。A3 中的 align@a 函数把要分组的集合（A1）分成几个子集，每个子集的分组键与基准序列成员一一对应，即分组键值与基准序列成员相同的记录（要分组序列的成员）分到同一组，这样得到的分组子集的数量和顺序由基准序列决定。如果某个基准序列成员不对应任何要分组序列成员的分组键值，它会对应一个空子集。

有了分组子集序列，计算由分组键值和汇总值组成的序表就很容易了。注意 A4 中的 new() 函数，应该用 A2(#) 来获取分组键值，因为有些分组子集可能是空的，无法从分组子集中获取这个信息。

SPL 只提供了生成分组子集的方法，没有进一步提供简化函数来一次计算汇总值。一方面，写起来不难。另一方面，对齐分组不如等值分组常用。

让我们再举一个例子：在之前的订单数据中，我们想按月计算最近两年的销售额，不管某个月有没有订单。

|   |   |
|---|---|
| =T("data.xlsx") |   |
| =to(202001,202012)|to(202101,202112) |   |
| =A1.align@a(A2,month@y(OrderDate)) |   |
| =A3.new(A2(#):ym,~.sum(Amount),~.count(Amount)) |   |

在这个分组中，不仅可能出现空集，而且原集合的某些记录可能不会被分到任何子集（那些不在最近两年的订单）。

细心的读者可能发现 align() 函数有一个选项 @a，那么没有选项时是什么操作呢？

它用于排序。

类似于对齐分组，我们有时需要按我们想要的顺序排列一批数据，而不是常规的字母或编码顺序。

在这个订单表中，我们想按地区计算销售额，但结果应该按 East、West、North、South、Center 的顺序排列。当然，我们可以用刚学的 align@a。

|   |   |
|---|---|
| =T("data.xlsx") |   |
| [East,West,North,South,Center] |   |
| =A1.align@a(A2,Area) |   |
| =A3.new(A2(#):Area,~.sum(Amount),~.count(Amount)) |   |

如果我们确定每组最多只有一项，可以用另一种写法：

|   |   |
|---|---|
| =T("data.xlsx") |   |
| [East,West,North,South,Center] |   |
| =A1.groups(Area;sum(Amount),count(Amount)) |   |
| =A3.align(A2,Area) |   |

在 A3 分组聚合后得到的序表中，每个地区最多有一条记录（可能没有记录）。不带选项的 align() 函数可以按 A2 的顺序重新排列这些记录。

对齐排序比对齐分组更常见。人们有很多约定俗成的固定排序顺序。例如，中国的省份排名通常把北京排第一，而不是按 unicode 顺序把安徽排第一。美国人没有这种固定的地区排序概念，但他们也有像 Sunday、Monday、Tuesday... 和 Low、Medium、High 这样不能直接按字母顺序排序的约定。

还有一种非常常见的对齐分组。分组键值是从 1 开始的正整数，目标顺序是按数字从小到大排列。例如，月份是数字 1-12，工作日也是 1-7 的整数。这种情况也叫做**序号分组**。

SPL 在 group() 和 groups() 函数中提供了 @n 选项来支持序号分组。

|   |   |
|---|---|
| =T("data.xlsx") |   |
| =A1.groups@n(month(OrderDate):M;sum(Amount),count(Amount)) |   |

使用时，与不带 @n 的 groups() 非常相似，但它是对齐分组，允许生成空集。如果分组键值小于 1，也会被丢弃。试试我们之前生成的股票数据：

|   |   |
|---|---|
| =100.new(now()-100+~:dt,rand()*100:price) |   |
| =A1.select(day@w(dt)>1 && day@w(dt)<7) |   |
| =A2.groups@n(day@w(dt):wday;min(price):min_p,max(price):max_p) |   |

A3 返回的序表会有 6 条记录，其中第一条对应周日的分组子集是空集（它的分组键值应该是 1），因为周日的数据在 A2 中被过滤掉了，剩余数据中最大的分组键值是 6（周六数据被过滤掉了，算不出 7），所以结果序表有 6 条记录。第一条记录对应空的分组子集，两个聚合字段都是 null，但分组键值字段仍然有值。

这里的分组键值没有减 1，会是 2、...、6，对应周一、...、周五，这与之前的计算结果不同。

我们也可以改成让分组键减 1。

|   |   |
|---|---|
| =100.new(now()-100+~:dt,rand()*100:price) |   |
| =A1.select(day@w(dt)<7) |   |
| =A2.groups@n(day@w(dt)-1:wday;min(price):min_p,max(price):max_p) |   |

A2 中只过滤掉周六数据，A3 分组时分组键值减 1，这样周日数据的分组键值会被计算为 0 并被丢弃。A3 会计算出 5 条记录（没有周六数据，最大是 5），这与之前的结果相同。

从这两个例子可以看出，序号分组不是以序号为分组键值的普通分组。它的行为更像对齐分组。可能出现空集，没有对应分组子集的成员会被丢弃。

group() 使用 @n 的效果与 groups() 类似，这里不再详述。

序号分组的另一个优点是计算速度快，因为可以直接用序号找到正确的分组子集，不需要比较操作。

除了常规的对齐分组，还会出现条件分组，最常见的是按段分组。例如，按年龄把人分成几组，或按金额把订单分成不同的组。

例如，我们按 BMI 值把之前的人员表分成四组：<20，体重不足；20-25，正常；25-30，超重；>30，肥胖。然后计算每组的平均身高。

|   |   |
|---|---|
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |   |
| [?<20,?>=20 && ?<25,?>=25 && ?<30,?>=30] |   |
| [UnderWeight,Normal,OverWeight,Fat] |   |
| =A1.enum(A2,weight/height/height) |   |
| =A4.new(A3(#):Grade,~.avg(height):avg_height) |   |

不同级别的条件写成字符串形成序列，其中 ? 表示要代入计算的分组键值。enum() 函数会用要分组集合中每个成员的分组键依次计算这些条件。如果得到 true，该成员会被分到对应的组。最终的分组子集在数量和顺序上也与这些基准条件对应。

这种分组叫做**枚举分组**。显然，枚举分组也可能得到空集，有些成员可能不会被分到任何组。

类似地，SPL 只提供 enum() 函数来返回分组子集。要得到汇总值，需要我们自己进一步计算。与对齐分组不同，枚举分组通常有另一个序列来标识每组的名称（这里的 A3）。

因为按段分组非常常见，这种情况也可以用之前讲的 pseg() 函数转换成序号分组，写起来更简单，执行也更快。

|   |   |
|---|---|
| ... |   |
| [20,25,30] |   |
| [UnderWeight,Normal,OverWeight,Fat] |   |
| =A1.group@n(A2.pseg(weight/height/height)+1) |   |
| =A4.new(A3(#):Grade,~.avg(height):avg_height) |   |

这里用 group@n() 先计算分组子集。因为 pseg() 函数对于小于第一个成员的情况会返回 0，需要加 1 作为分组键值，否则这个段会被丢弃。

直接用 groups() 计算汇总值也可以，但需要再做一步来正确填入段标识，否则我们会看到分组键值本身，即 1、2、3、...

|   |   |
|---|---|
| ... |   |
| [20,25,30] |   |
| [UnderWeight,Normal,OverWeight,Fat] |   |
| =A1.groups@n(A2.pseg(weight/height/height)+1:Grade;avg(height):avg_height) |   |
| =A4.run(Grade=A3(Grade)) |   |

实际上，对齐分组可以看作是特殊的枚举分组。所有对齐分组都可以用枚举分组来写。

|   |   |
|---|---|
| ... |   |
| [?=="Male",?=="Female"] |   |
| [Male,Female] |   |
| =A1.enum(A2,sex) |   |
| =A4.new(A3(#):sex,~.avg(height):avg_height,~.max(weight):max_height) |   |

enum() 函数也支持重复分组（即一个成员可能被分到多个分组子集），但因为不太常见，我们不讲了。需要时可以查帮助。

SQL 只有等值分组，遇到枚举分组（包括对齐分组）的计算需求时非常麻烦。
