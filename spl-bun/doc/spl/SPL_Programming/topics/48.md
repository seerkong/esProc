## 提取内容

当我们讨论结构化数据的概念时，我们说数据表的字段有名称，但记录没有名称。那么我们如何区分一条记录和另一条记录呢？我们知道每条记录对应一个事物的信息。是哪一个？如何确定当前引用或操作的记录就是对应预期事物的那条记录？

使用记录在表序列中的顺序来标识通常是不可靠的，因为序号会随着插入和删除操作而改变。

在前一章的例子中，我们创建和引用的大多数表序列都有一个字段，其值在整个表序列中是唯一的，如人员表中的 id 字段或股票表中的 dt 字段。结构化数据使用这个唯一的字段值来标识一条记录。

在数据表中，如果有一个或多个字段，且任意两条记录在该字段（如果是多个字段则是值的序列）的值都不同，我们可以将该字段（字段组）设置为数据表的**主键**。

注意，主键是手动设置的，而不是自动发现的。数据表中可能有多个字段（或字段组）满足主键的条件（唯一性），但我们只会选择一个（组）作为主键。主键必须是唯一的，但唯一的字段不一定是主键。

记录的主键字段值，也称为记录的**主键值**，在上下文明确时也简称为**主键**。

因为主键是唯一的，即一条记录的主键值在整个数据表中不会重复，所以主键可以用来唯一标识一条记录。我们说当前引用或操作的记录是主键为 xxx 的记录，这样就只有一条这样的记录，不会出错。

对于已经设置了主键的数据表，原则上不允许添加与现有记录主键相同的新记录。在插入和删除记录时，主键不会改变。使用主键来标识记录比使用序号更稳定。

然而，主键不是必需的（前面的例子都没有主键）。没有主键的数据表通常只追加记录，而不是修改、删除现有记录或在前面插入新记录，因为这些操作会改变序号。

实际上，我们在日常生活中对主键的概念并不陌生。学校里的所有学生都会有一个唯一的学号。学号属性本身没有有效信息，它的作用只是唯一标识一个学生。直接使用学生姓名是行不通的。人们经常会有重名，所以很难准确识别一个学生。对于订单这样的东西，它们没有名称。需要一个（唯一的）编号来标识它们。否则，我们不知道如何确定我们在谈论哪个订单。其他类似的还包括航班号、银行账户、电话号码等，它们都起着主键的作用。

日常生活中的"主键"几乎无处不在。结构化数据的主键只是人们日常经验在编程语言中的体现。主键是记录的名称。设置主键就是给记录一个（唯一的）名称。

SPL 提供了一些主键相关的函数：

| =1000.new(string(1000+~):id, if(rand()<0.5,"Male","Female"):sex) |
| =A1.keys(id) |
| =A1(1).key() |

A2 使用 keys() 函数将表序列的主键设置为 id 字段，A3 使用 key() 计算一条记录的主键。

对于设置了主键的表序列，在显示值时会在主键字段上绘制一个钥匙图标。

然而，SPL 在设置主键时不检查主键的唯一性。主键是否唯一由程序员自己控制。

使用我们学过的分组操作，很容易判断一个字段在数据表中是否唯一：

| =1000.new(string(rand(1000)):id, if(rand()<0.5,"Male","Female"):sex) |
| =A1.id().len()==A1.len() |

只需看看 DISTINCT 后的序列是否与原表序列一样长。

在插入记录时，SPL 不检查主键的唯一性。以下代码不会报错。

| =1000.new(string(1000+~):id, if(rand()<0.5,"Male","Female"):sex) |
| =A1.keys(id) |
| =A1.insert(1,"1002") |

SPL 只在需要时才检查主键的唯一性。这样做的好处是计算性能更好，每次检查都是耗时的操作，但缺点是可能存在潜在错误。SPL 的原则是完全相信程序员，把自由留给程序员。

主键的主要用途是标识记录，即用主键值查找记录。

| =1000.new(string(1000+~):id, if(rand()<0.5,"Male","Female"):sex) |
| =A1.keys(id) |
| =A1.find("1053") |

SPL 使用 find() 函数返回主键为其参数的记录。如果找不到，将返回 null。

在我们现在用作示例的表序列中，记录的主键像序号一样从小到大排列。这是为了方便生成唯一字段（如果随机生成，需要比较是否重复）。然而，SPL 对主键没有这个要求。它可以是无序的：

| =1000.(string(1000+~)).sort(rand()) |
| =1000.new(A1(#):id, if(rand()<0.5,"Male","Female"):sex) |
| =A2.keys(id) |
| =A2.find("1053") |

A4 也可以正常找到以参数为主键的记录。

由于 SPL 不检查主键的唯一性，如果表序列中有主键相同的记录，find() 函数不会报错。它会找到第一条记录并返回，这有点像 select@1()。

顺便说一下，find() 类似于 pos()。它不是循环函数。它的参数在调用时会先计算，不会有 ~、# 等。

使用主键查找记录是一个常见的操作。如果表序列比较大，搜索速度会很慢，因为这种搜索通常需要逐一比较。

SPL 提供了一种对主键建立索引的机制，搜索速度会快很多。

| =1000.(string(1000+~)).sort(rand()) |
| =1000.new(A1(#):id, if(rand()<0.5,"Male","Female"):sex) |
| =A2.keys(id) |
| =now() |
| >10000.run(A2.find(string(1000+rand(1000)))) |
| =now() |
| =interval@ms(A4,A5) |
| >A2.index() |
| =now() |
| >10000.run(A2.find(string(1000+rand(1000)))) |
| =now() |
| =interval@ms(A7,A8) |

index() 函数会为有主键的表序列创建索引，创建索引后 find() 会自动使用索引。

当你执行这段代码并比较索引前后的运行时间时，你会发现性能差距非常大（但也需要执行 10000 次并使用 interval@ms() 来捕获）。提供索引后，不再使用逐一比较的方法。具体方法远超本书内容，这里不再解释。

SPL 在创建索引时要求主键的唯一性。执行 index() 时，SPL 会检查主键是否唯一。如果此时发现主键不唯一，会报告主键重复的错误信息。

SPL 似乎有点懒，在必要之前不会主动做事。

与前面提到的操作不同，主键和索引只能为表序列创建，不能为记录序列创建。它们是数据结构的一部分。

然而，find() 可以用于记录序列，只是不能使用索引。只能逐一比较。

顺便说一下，如果主键是有序的，find() 也支持一种叫做二分查找的快速搜索技术，比逐一比较快得多（接近索引，但仍然赶不上）。它可以用于没有索引的记录序列或没有创建索引的表序列。select() 函数和 pos() 函数也支持这种二分查找。有兴趣的读者可以参考 SPL 的相关文档，因为高性能计算不是本书的重点（我们刚才也没有讲索引的原理），这里不再详述。

让我们回顾一下前一章提到的分组操作。观察 groups() 返回的表序列，很明显对应分组键值的字段是唯一的，即这个字段可以自然地构成 groups() 返回的表序列的主键。因此，用于分组的字段值被称为键。细心的读者可能已经发现，在查看 groups() 的返回结果时，分组键上已经绘制了小钥匙图标。
