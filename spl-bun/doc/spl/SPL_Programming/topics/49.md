## 提取内容

有了主键，我们可以唯一标识一条记录。然后，我们可以建立不同数据表记录之间的关联。

首先，生成两个有主键的表用于实验。为简单起见，我们使用整数作为主键，但顺序是故意打乱的。

| [HR,R&D,Sales,Marketing,Admin] |
| =A1.len().sort(rand()) |
| =100.sort(rand()) |
| =A1.new(B1(#):did, ~:name, C1(#):manager).keys(did) |
| [CHN,USA] |
| =100.new(C1(#):eid, C2(rand(2)+1):nation,rand(5)+1:dept).keys(eid) |
| =A2.run(A3(manager).dept=did) |

A2 是部门表，每条记录对应一个部门，did 字段是部门编号，用作主键，name 字段是部门名称；A3 是员工表，每条记录对应一个员工，eid 字段是员工编号，用作主键，nation 字段是员工的国籍。员工表通常有 name 字段，但这里用不到，所以我们不生成它。

关键是 A3 的 dept 字段和 A2 的 manager 字段。dept 存储一个整数，表示员工所属的部门。员工表中记录 e 对应的员工的部门是部门表中以 e.dept 为主键的记录 d 对应的部门。我们也会说记录 e 与记录 d 关联。

A2 的 manager 字段表示部门的经理。经理也是员工，也会出现在员工表中。部门表中记录 d 对应的部门的经理是员工表中以 d.manager 为主键的记录 e 对应的员工。我们也说这两条记录 d 和 e 是关联的。

理解了这种关系，A4 的作用就清楚了。因为随机生成的数据不能保证经理的部门是他自己的部门，所以需要在 A4 中调整，以便使用这些数据。

现在我们想列出研发部门的所有人员。

这是一个简单的选择问题，我们应该使用 select() 函数。然而，员工表中没有部门名称，只有部门编号。

只能通过使用编号在部门表中查找部门名称来进行选择。

| … |
| =A3.select(A2.find(dept).name=="R&D") |

同样，我们也可以列出经理是美国人的所有部门：

| … |
| =A2.select(A3.find(manager).nation=="USA") |

这样，我们将员工表与部门表关联起来，可以联合使用两个表的信息进行操作。员工表中的 dept 字段始终是部门表中某条记录的主键，它也用于表示部门表中的这条记录。我们称这个字段为**外键**，更完整的说法是员工表中指向部门表的外键。通过外键，我们可以在一个表的操作中引用另一个表中关联记录的某些字段，两个表通过外键关联。

同样，部门表中的 manager 字段也是指向员工表的外键。

主键可能由多个字段组成，相应地，外键也可能有多个字段，但这相对不常见，这里不举例。

当两个表之间存在外键关系时，例如表 A 中的一个字段是指向表 B 的外键。我们还需要知道两个术语：表 B 是表 A 的**维表**，表 A 称为**事实表**。维表和事实表的关系是相对的。当我们关心员工表的外键 dept 时，部门表是员工表的维表，而当我们关心部门表的外键 manager 时，员工表是部门表的维表。

维表和事实表是程序员在讨论数据库操作时经常使用的术语。我们在日常数据处理中不使用这种技术词汇，但最好了解一下。

在数据库术语中，也说外键关联是**多对一关联**，即多条事实表记录可能与同一条维表记录关联。

外键不是一个陌生的概念。维表就是我们经常使用的代码表。我们在代码表中列出事物的一些经常被引用的属性，并给出一个代码（即主键）来标识它们。引用时，我们只使用这个代码（即外键），要获取更详细的信息，我们用这个代码查询代码表。

例如，机主的姓名、地址等信息会与电话号码一起列出，而通话记录中只有电话号码。电话号码是电话簿的主键。通话记录中的电话号码是指向电话簿的外键。电话簿是通话记录的维表，通话记录是事实表。在通话记录的计算中，经常可以使用与电话号码相关的信息，如查询北京打出的电话数量，这就是使用外键查找关联记录的字段。

还有其他的，如银行账户和银行交易记录、商品信息和交易记录。

在事实表的操作中使用维表信息是非常常见的。为什么我们不直接把维表字段复制到事实表中呢？

有使用代码表经验的读者会知道答案。维表中有很多信息内容。如果复制到事实表中，事实表会非常大，占用大量存储空间，导致性能低下。而且，维表很可能会变化，如部门名称和机主地址。如果复制到事实表中，一旦变化，事实表就要更新，而事实表通常大得多，非常麻烦且效率低下。如果是独立的维表，只需修改维表，在事实表操作时临时获取维表字段，就可以始终获得最新信息。

理解了概念，让我们继续。现在将员工 id（用 id 字段代替，不生成 name 字段）和部门名称列成一个表：

| … |
| =A3.new(eid,A2.find(dept).name:dept) |

这与 Excel 中的 VLookup 函数非常相似。代码表就是这样使用的。

然而，总是用 find() 来写显然很麻烦，而且每次都计算效率很差。例如，如果我们想列出员工所在部门经理的 id，我们必须写两次 find()。

| … |
| =A3.new(eid,A2.find(dept).name:dept,A2.find(dept).manager) |

这更像 VLookup。Excel 必须写两次 VLookup 才能引用关联表的两列。

SPL 显然不会不考虑这个问题。这种结构化数据的常规操作不能这么麻烦。SPL 提供了 switch() 函数来实现外键的关联操作：

| … |
| >A3.switch(dept,A2) |
| =A3.new(eid,dept.name:dept,dept.manager) |

switch() 函数会将外键字段切换为对应的维表记录。A5 代码相当于执行以下语句：
>A3.run(dept=A2.find(dept))

dept 字段的值已经变成了一条记录。双击它会显示这条记录的详细信息。刚才显示的颜色变化的值实际上是这条记录的主键。

既然是记录，当然可以引用它的字段，A6 中的 dept.name 和 dept.manager 可以正常计算。

函数名 switch() 的使用是因为它也可以将值为记录的字段切换回来：

| … |
| >A3.switch(dept,A2) |
| =A3.select(dept.name=="R&D") |
| >A3.switch(dept) |

A5 将外键切换为维表的记录，A6 可以用它来引用维表记录的字段。A7 将现在值为记录的字段切换回来。A7 相当于执行：
>A3.run(dept=dept.key())

然而，切换回来的情况很少见。

经过 switch() 处理后，两个表的记录似乎真的连接在一起了。这个表的字段值是另一个表的记录。你可以通过这个字段引用另一个表的字段。这比 VLookup 方便多了。

相应地，部门表中的 manager 字段也是外键，也可以切换为人员表中的记录。

例如，我们想统计有多少美国员工的经理是中国人：

| … |
| >A3.switch(dept,A2) |
| >A2.switch(manager,A3) |
| =A3.count(nation=="USA" && dept.manager.nation=="CHN") |

外键关系可能有多层。在这种情况下，如果我们仍然使用 find() 方法来描述会很困难（有兴趣的读者也可以尝试思考如何在 Excel 中使用 VLookup 实现这种多层关联）。对于用 switch() 函数切换的外键，点运算符可以形象地解释为"的"。A6 中的 dept.manager.nation 可以解释为当前员工的部门的经理的国籍。即使有很多层，你也不会觉得困难。这样的语法写起来简单，理解起来容易。

一般来说，外键字段的值必须在维表主键值的范围内，但有时可能会超出范围。例如，在新员工的部门确定之前，dept 字段填写为 0，而部门表中没有对应的记录。

| … |
| =A2.run(A3(manager).dept=did) |
| >C1.to(90,).run(A3(~).dept=0) |
| =A3.switch(dept,A2) |
| =A5.count(dept.name==null) |
| =A3.switch@i(dept,A2) |
| =A5.count(dept.name==null) |
| =A3.switch@d(dept,A2) |
| =A5.count(dept.name==null) |

在生成数据的代码 B4 中，我们故意找一些员工的 dept 填写为 0，然后可以观察三个 A5 的计算结果。注意应该分别执行，而不是顺序执行，因为执行后 A3 会改变，继续执行另一个 A5 没有意义。

当 switch() 找不到外键对应的维表记录时，会将外键填充为 null，后续引用其字段不会报错，但会返回 null，对应的 B5 不会是 0。@i 选项会删除找不到外键对应记录的事实表记录，确保 switch 后事实表记录的所有外键都正确切换为维表记录，对应的 B5 会返回 0。而 @d 选项只保留找不到外键对应记录的事实表记录，不能执行外键切换，对应的 B5 会报错。

使用外键关联两个数据表通常用于临时将维表的一些字段连接到事实表（即 VLookup 做的事情）。在大多数情况下，并不打算改变事实表的字段。虽然 switch() 函数对关联操作很方便，但它会改变原事实表的外键字段值。如果我们只想追加维表字段，需要再做一步将已变成记录的外键切换回外键，这很麻烦。而且，如果遇到我们刚才提到的没有对应的情况，外键会被填充为 null，信息已经丢失，无法切换回来。

SPL 提供了 join() 函数来实现这个目标：

| … |
| =A2.run(A3(manager).dept=did) |
| >C1.to(90,).run(A3(~).dept=0) |
| =A3.join(dept,A2,name:deptname,manager:manager) |

A5 会在表序列 A3 的基础上添加 deptname 和 manager 字段，分别填入员工的部门名称和经理 id。dept 字段将保持不变。如果找不到对应的维表记录，新添加的字段将填充为 null。

join() 函数会生成一个新的表序列，原来的 A3 不会改变。

join() 函数也可以支持多字段主键和外键。因为不常见，这里不举例。需要使用时，可以查阅 SPL 的相关文档，了解多层参数的必要性。

switch() 函数不支持多字段主键的维表。它只能切换单字段外键。

使用外键在维表中查找对应记录以引用关联记录的某些字段是非常常见的。然而，业务是复杂的。有时关联记录不能简单地通过外键确定，而需要与区间相关的条件。

回到前一章经常使用的人员表，创建一个 BMI 对照表：

| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |
| =A1.derive(weight/height/height:bmi) |
| [null,20,25,30] |
| [UnderWeight,Normal,OverWeight,Fat] |
| =A3.new(~:low,~[1]:high,B3(#):type) |

现在我们想在人员表 A2 中添加一个带有 BMI 信息的字段，列出每个人的体重类型。

如果将 BMI 对照表 A3 用作维表（有要引用的字段），它有 low 和 high 字段表示某种体重类型的 BMI 区间，但没有适合作为主键的字段（虽然 low 和 high 是唯一的）。人员表 A2 中似乎也没有可以充当外键的字段。然而，很明显 A2 和 A4 之间存在关联，A2 的每条记录都会对应 A4 的一条记录。

区间关联也是一种常见的关联。应该如何实现？

我们当然可以简单地使用 select() 函数，就像本节开头使用 find() 一样。

| … |
| =A2.derive(A4.select@1(low<=bmi && (!high || high>bmi)).type) |

这里需要判断 high 是否为 null（表示最后一段），low 不需要判断，因为 SPL 规定 null 是最小的，null<=bmi 总是得到 true。

实际上，区间关联也可以理解为外键关联。如果我们修改 BMI 对照表，并将 pseg() 函数计算的 BMI 段号添加到人员表中，就可以看到外键关系。

| … |
| [null,20,25,30] |
| [UnderWeight,Normal,OverWeight,Fat] |
| =A3.new(#:no,~:level,B3(#):type).keys(no) |
| =A2.derive(A4.(level).pseg(bmi)+1:bmitype) |
| =A5.switch(bmitype,A4) |

修改后的 BMI 对照表 A3 有主键，可以用作维表。A5 中添加的 bmitype 字段是指向 A3 的外键。我们也可以使用 switch() 建立关联。

区间关联本质上也是外键关联。

为人员表创建外键确实很麻烦。实际上，我们写上面的代码是为了帮助你理解外键的概念可以扩展到这种情况。实际上，我们可以直接用 pseg() 拼出目标字段。

| … |
| [null,20,25,30] |
| [UnderWeight,Normal,OverWeight,Fat] |
| =A3.new(~:level,B3(#):type) |
| =A2.derive(A4(A4.(level).to(2,).pseg(bmi)+1).type) |

一般来说，区间关联处理不会生成外键，但维表和事实表的概念仍然可以使用。

如果像这个例子一样，只需要引用 type 字段，我们甚至不会生成对照表，而是直接使用序列和 pseg() 来计算和引用。

| … |
| [20,25,30] |
| [UnderWeight,Normal,OverWeight,Fat] |
| =A2.derive(B3(A3.pseg(bmi)+1):type) |

像所有外键关联一样，区间关联也是多对一关系。即使不生成维表，这种关联关系在逻辑上仍然存在。
