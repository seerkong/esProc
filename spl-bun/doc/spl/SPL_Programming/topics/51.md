## 提取内容

让我们继续看上面的订单例子。在挑出两个文件中订单号相同但内容不同的记录后，我们想把字段（除订单号外）拼在一起进行比较。即形成一个字段数翻倍（除订单号外）的数据表。

我们通常使用 join() 函数来完成这个任务。

| =T("data1.xlsx") |
| =T("data2.xlsx") |
| =[A1,B1].merge@i(ID) |
| =[B1,A1].merge@i(ID) |
| =join(A2:a,ID;B2:b,ID) |
| =A3.new(a.ID:ID,a.Company:CompanyA,b.Company:CompanyB, a.Area:AreaA,b.Area:AreaB,a.OrderDate:OrderDateA,b.OrderDate:OrderDateB, a.Amount:AmountA,b.Amount:AmountB, a.Phone:PhoneA, b.Phone:PhoneB) |

A3 的 join() 函数返回一个有两个字段的表序列，分别是 a 和 b。它会根据 ID 字段值将 A2 和 B2 中的记录连接起来，即把 ID 相同的 A2 记录和 B2 记录分别填入字段 a 和字段 b，作为返回表序列中的一条记录。字段 a 或字段 b 的值也是一条记录，这有点像外键被切换后的结果。理解了 A3 的计算结果后，虽然 A4 很长，但很容易理解。

与 merge() 不同，join() 的任务通常是使数据表变宽，而 merge@u 会使数据表变长（更多记录）。

与 merge() 更大的区别是，merge() 针对的数据表通常具有相同的数据结构。而 join() 的常见场景是两个（或更多）具有不同数据结构的数据表。

让我们继续使用之前生成的人员表，我们现在有一个包含性别、身高和体重的人员表，以及一个包含国籍和部门的员工表。我们想把两个表做成一个更宽的表。如果人员表的 name 字段与员工表的 eid 字段相同，就表示是同一个人。

让我们整理一下用于生成数据的代码。我们暂时不使用部门表，直接丢弃它。

| =100.sort(rand()) |
| [HR,R&D,Sales,Marketing,Admin] |
| [CHN,USA] |
| =100.new(A1(#):eid, C1(rand(2)+1):nation,B1(rand(5)+1):dept) |
| =100.new(string(~):name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height) |

员工表 A2 中的 eid 是无序的。让我们完成任务：

| … |
| =join(A3:P,int(name);A2:E,eid) |
| =A4.new(P.name,P.sex,P.weight,P.height,E.nation,E.dept) |

因为 A3 的 name 是字符串类型，与 A2 的 eid 不同，需要转换，写成 int(name)。我们也可以转换 A2，把 A4 写成：

两个数据表可以通过某些字段（或表达式）之间的相等关系生成一个有两个字段的数据表。基于这个新数据表，可以同时引用两个原数据表的字段进行操作，从而完成两个表的关联。用于确定关联的字段（表达式）称为**关联键**，关联键值相等的记录称为**关联记录**。这种关联操作称为**连接**。

前一节提到的外键关联也是一种连接操作。它使用事实表的外键和维表的主键作为关联键。然而，我们很少将外键关联的操作结果表示为使用两个以记录为值的字段作为数据结构的表序列。相反，我们习惯于使用前面的方法，用 switch() 函数切换外键或用 join()（不是我们正在讨论的 join()）将维表字段拼入事实表。

如果我们已经为 A2 和 A3 表设置了主键，在 join() 时就不需要写关联键。

| =100.sort(rand()) |
| [HR,R&D,Sales,Marketing,Admin] |
| [CHN,USA] |
| =100.new(A1(#):eid, C1(rand(2)+1):nation,B1(rand(5)+1):dept).keys(eid) |
| =100.new(~:name, if(rand()<0.5,"Male","Female"):sex,50+rand(50):weight,1.5+rand(40)/100:height).keys(name) |
| =join(A3:P;A2:E) |

我们需要修改 A3 中的生成语句，直接使用整数作为 name 字段的值，这样两个表的主键就不需要转换，直接作为关联键。

使用主键作为关联键的连接称为**同维关联**，两个表也互称为**同维表**。在数据库术语中，同维关联是**一对一关联**，即关联表中的一条记录只会与另一个关联表中的一条记录关联，而不是多条，因为主键是唯一的。

让我们继续这段代码，稍作修改。A2 从 1 到 100 之间随机选择 80 个整数作为主键生成 80 条记录；A3 直接选择 1-90 作为主键生成 90 条记录。这样，A2 和 A3 的主键仍然有很多共同点，但也有少量对方没有的主键值（由于随机生成，每次运行的结果可能不同，但不影响我们的讨论）。

| =100.sort(rand()) |

join() 函数会在两个表中找到关联键相等的记录进行关联。如果一个表的关联键值在另一个表中不存在，这个表的对应记录也会被丢弃。这种连接称为**内连接**。计算出的表序列结果中的关联键集合是两个关联表序列的关联键集合的交集，即上面代码中的 B5，A5 必然等于 C5，通常小于 A2 或 A3 的长度。

修改最后两行代码后再试一次：

| … |
| =join@1(A3:P;A2:E) |
| =A4.len() |
| =A3.(name) |
| =B5.len() |

再次执行，然后看 A4：

（原文含示意图，图像资源未迁移）

P 字段值中的记录主键是完整的，从 1 到 90，与 A3 的记录一一对应。E 字段的一些记录填充为 null。A5 也是 90，与 A3 长度相同。

带 @1 的 join() 会以左边的关联表（第一个参数）为基准。如果右表中有与左边关联键相同的记录，就会关联。如果没有记录，就填充为 null。结果表序列的关联键值与左表相同，长度也与左表相同。

这种以左边为基准的连接称为**左连接**。

一些数据库系统也有右连接，即以右边为基准的连接。然而，SPL 不提供它。这是不必要的，因为可以通过交换参数位置来实现。

这个 @1 是数字 1，不是字母 l。它表示 join() 以第一个参数为基准。

因为 A3 的主键是从 1 到 90，前面的记录都存在。把表拉到最后，可以看到最后几条记录。

现在左右两边都有 null 字段值，A5 大于 90，但通常不是 100。

带 @f 的 join() 会考虑两个表。如果关联键值在任何一边存在，就会在结果表序列中生成一条记录。如果两边都有关联键值的记录，记录会填入对应字段实现关联。对于一个关联键值，如果只有一个表有对应记录，就填入对应字段，另一个表的对应字段填充 null。最后，结果表序列中的关联键值集合将是参与关联的两个表序列的关联键集合的并集，即代码中的 B5，A5 将与 C5 相同，通常大于 A2 或 A3 的长度。

这种双边连接称为**全连接**。

内连接、左连接和全连接是非常重要的概念。在执行连接操作时，我们必须确定使用哪种连接。不同连接的结果会非常不同。

外键关联通常是左连接，即以事实表为基准。如果 switch() 函数在维表中找不到关联记录，会将外键字段填充为 null。而 switch@i() 相当于内连接。当找不到关联记录时，事实表的相关记录也会被过滤掉。

join() 和 join@f() 与 merge@i() 和 merge@u() 有点相似。实际上，连接操作可以用来根据主键实现两个表序列的交集和并集。

一份数据可能有多个生产来源，然后拼接成完整的数据。它可能按行（记录）分成多个部分，用 merge() 合并，在过程中处理重复部分。它也可能按列（字段）分成多个部分，用 join() 合并。这些数据也需要合理连接，不能错位。

让我们看另一个关联案例：

| =100.sort(rand()) |
| [HR,R&D,Sales,Marketing,Admin] |
| [CHN,USA] |
| =100.new(A1(#):eid, C1(rand(2)+1):nation,B1(rand(5)+1):dept).keys(eid) |
| =A2.news(12;eid,~:m,5000+rand(5000):salary).keys(eid,m) |

基于员工表，为每个人生成 12 个月的工资表。A3 需要两个字段作为主键（以确保唯一性）。

现在我们想计算每个部门的总收入。

部门信息在员工表中，而收入信息在工资表中，这个任务需要两个表的关联。

使用我们学过的外键关联，将员工表视为工资表的维表，我们可以解决问题：

| … |
| =A3.switch(eid,A2) |
| =A4.groups(eid.dept;sum(salary)) |

这段代码没有问题。然而，我们也可以使用 join() 来处理这种使用主键的一部分作为外键的关联。

| … |
| =join(A2:E;A3:S,eid) |
| =A4.groups(E.dept;sum(S.salary)) |

计算出与刚才相同的正确结果。

看 A4。结果如下：

（原文含示意图，图像资源未迁移）

A2 记录在 E 字段中重复。每条 A3 记录与一条 A2 记录关联，而每条 A2 记录与 12 条 A3 记录关联。A4 的长度与 A3 相同。

这种使用主键字段的一部分作为外键的关联，也称为**主子关联**。主键字段较少的表称为主表，主键字段较多的表称为子表。主子关联是一对多关联，与外键关联相反。从子表的角度看主表，是外键关系，而从主表的角度看子表，是主子关联。

我们也会使用这个 join() 来处理主子关联，而不是总是使用 switch() 和前一节提到的 join()。有时，我们会先对子表做 groups()，然后与主表 join()。例如，对于前面的问题：

| … |
| =A3.groups(eid;sum(salary):salary).keys(eid) |
| =join(A2:E;A4:S) |
| =A5.groups(E.dept;sum(S.salary)) |

A4 执行分组聚合后，形成一个以分组键为主键的表序列，与 A2 具有一对一的同维关系。

理论上，在外键关联中，我们也可以使用外键作为分组键对事实表执行 groups()，形成与维表具有同维关系的表，但我们通常不这样做，因为事实表通常有多个外键。如果我们根据一个外键执行 groups()，其他外键就无法处理。在大多数情况下，子表只有一个主表，所以根据关联键执行 groups() 然后与主表做同维关联是没有问题的。

当然，在外键关联中，我们也可以像主子关联一样直接执行 join() 操作，把维表和事实表的记录放在一起。一条维表记录可能与多条事实表记录关联。实际上，外键部分提到的 join() 函数就是这样做的，但它还做了关联后引用维表字段的动作，因为这种组合动作更常见。结果表序列的长度也与事实表（主子关联概念中的子表）相同，所以函数也命名为 join()。

现在我们遇到了几种连接模式：一对一、一对多和多对一。有没有多对多模式？

在结构化数据操作中几乎没有业务意义上的多对多连接。多对多连接只存在于理论分析或数学运算中。日常数据处理中基本没有与主键无关的关联，所以我们不必关注它们。

SPL 提供了 xjoin() 函数来处理任意条件的连接，也可以实现多对多。但我们只能举一个数学例子来说明。

xjoin() 会计算参与关联的集合的笛卡尔积（注意我们说的是集合而不是表序列，因为很难为结构化数据找到合理的业务例子）。这个过程可以在指定条件下过滤笛卡尔积。

对于笛卡尔积的概念，不熟悉的读者可以在网上搜索。让我们举一个简单的例子来理解。

| [1,2,3] |
| [HR,R&D,Sales,Marketing,Admin] |
| [CHN,USA] |
| =xjoin(A1:a;B1:b) |
| =xjoin(A1:a;B1:b;C1:c) |
| =xjoin(A1:a;C1:c) |

A2、B2、C2 的计算结果不难理解。从每个集合中取一个成员组成一条记录，包含所有可能的组合，这就是笛卡尔积。也可以理解为多层循环，每层循环遍历一个集合。在最内层循环中，收集每层的循环变量组成一条记录。这些记录的集合就是结果表序列，其长度是参与计算的集合长度的乘积。

实际上，我们前面提到的所有关联都可以这样定义：从参与关联的数据表的笛卡尔积中取出满足某个条件的子集（我们学过的所有连接操作都可以使用"关联键值相等"的条件），SQL 就是这样定义连接操作的。这个定义非常简单，但它没有反映数据之间的关联特征，对简化语法或提高性能没有帮助。

SPL 不采用这个定义，而是分别描述常见的关联模式。你可以在不同场景中使用不同的操作方法。

让我们用 xjoin() 来实现之前用递归程序实现的排列生成：

| =to(A1) |
| =B1.("A2:_"/~).concat(";") |
| =xjoin(${B2}).(~.array()).select(~.id().len()==~.len()) |

A3 会计算从 1,2,3,4,5 中取三个成员的所有排列。

xjoin() 首先计算三个 to(5) 的笛卡尔积，然后过滤掉有重复成员的（id.len() ≠ len()），得到合理的排列。

可以修改 A1 和 B1 来获得其他值的排列。

这段代码看起来比递归简单得多，但计算量大得多。我们只能用较小的值来尝试。

我们用三章讲了结构化数据及其操作。这些内容已经远远超过了 SQL 的查询和计算能力，即关系数据库。只有最常见操作中的递归关联因为难度大、应用少而被放弃。

换句话说，学会了这些内容并能灵活组合，你处理结构化数据的能力将比只会使用 SQL 的专业数据库程序员更强。结合 Excel 和其他表格软件实现漂亮的展示，你可以轻松解决几乎所有日常数据处理的问题。
