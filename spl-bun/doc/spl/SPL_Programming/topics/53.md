## 提取内容

本章我们将讨论如何处理大数据。

这里所说的大数据是指无法加载到内存中的数据。它通常以文件形式存储在硬盘上或存储在数据库中（也在硬盘上）。

本书不涉及数据库，只涉及文件中的大数据。

Excel 文件通常不会太大（它有最大行数限制）。大文件通常是前面提到的 txt 或 csv 格式。根据现代计算机的内存，需要数千万甚至数亿行（记录数）的数据才算大，文件大小将是几 G 或几十 G 或更多。

实际上，我们在日常桌面工作中很少遇到如此大量的数据，所以前面提到的操作方法在大多数场景下已经足够。然而，作为一本完整的书，我们仍然介绍大数据的处理方法。

大数据和我们之前处理的数据有什么区别？我们之前学的方法不能用吗？

前几章描述的处理方法都是针对内存中的数据。使用的文件数据也是读入内存后处理的。

因为 CPU 只能直接处理内存中的数据，不能直接处理硬盘和其他非内存数据。

我们能不能这样做：给硬盘上的所有数据一个地址，需要使用时临时从硬盘读入内存，用完后丢弃，如果需要修改就写回硬盘，这样看起来就像直接操作一大块内存。

理论上是可以的。确实有些场景的程序这样做（Windows 有系统缓存来做这件事）。但结构化数据操作很难这样做。

这是因为内存和硬盘之间有什么本质区别吗？

是的，用 IT 术语来说，内存允许**随机小块访问**，即通过随机给出一块内存的地址就可以检索该地址下的数据。例如，使用序列时，我们可以用序号访问任何成员。

硬盘做不到这一点。

硬盘更适合**连续批量访问**。它只能读写整块，每次至少一个最小单位（具体大小与操作系统有关。目前大多数计算机是 4096 字节，字节用于衡量数据占用的空间。不理解也没关系，不影响你的理解），只读一个整数（只有 4 或 8 字节，压缩后会更小）也必须读入整块。如果读取各种地址的大量小块数据（访问很多地方，每个地方有一小块数据，这实际上是非常常见的情况），实际读取的数据量非常大，导致性能差。旧的机械硬盘不能支持高频随机访问（即使读取整块），性能下降非常严重。

由于这些麻烦，对于结构化数据操作的场景，没有人把硬盘模拟成内存。而且，更麻烦的是操作系统不为结构化数据做任何特殊工作。它只为硬盘上的数据读写文件，而操作文件是一件非常复杂的事情，这会进一步降低性能。

我们能做什么？

我们不能用之前的方法直接访问硬盘上的结构化数据。我们通常使用**游标**技术来完成操作。

当我们打开一个数据文件时，游标就像一个指针。首先它指向文件的第一条记录，然后可以将几条记录读入内存进行处理。在读取过程中，游标指针也会向前移动。内存中的数据处理完并丢弃后，再从游标的当前位置读取下一批进行处理，……，重复直到所有数据都读入内存并处理完毕。

因为游标每次会读取一批数据，通常占用硬盘的多个块，这实际上是批量连续访问，避免了硬盘的困难。

然而，由于大多数数据文件如 txt 和 csv 的特殊结构，游标通常只能向前移动，不能向后移动（向后移动的代价非常高）。

即使向前移动，也不能跳跃，只能逐行遍历。换句话说，用游标访问数据已经失去了随机性。

因此，前面提到的许多操作方法都不能使用。我们需要为游标设计一套函数。

让我们来谈谈游标相关的函数。

为了做实验，我们首先生成一个大文件，一个简化的订单表。

| [East,West,North,South,Center] |
| for 0,999 |
| =10000.new(A2*10000+~:id,A1(rand(5)+1):area,date(now())-1000+A2:dt,1+rand(10000):amount,1+rand(100):quantity) |
| =B2.select(rand()>=0.01) |
| >file("data.txt").export@at(B3) |

export() 函数会将表序列写入文件，@a 选项表示追加写入。这样，文件会被追加 1000 次，每次写入不到 10000 条记录（B3 中会随机丢弃一部分），总共不到 1000 万条记录。@t 表示文件的第一行写入字段名作为标题，这与 xlsimport() 中的 @t 相同。

id 字段可以充当主键，但在文件数据中不能真正建立主键。dt 是日期。每次生成的数据是同一天的，并随循环变量 A2 增加，这可以确保日期是有序的（后面会用到），需要丢弃 now() 的时间信息。amount 和 quantity 可以随机生成。

注意执行前应删除原来的 data.txt，否则会在当前文件后面添加一批数据。另外，实际使用时最好加上文件的绝对路径，否则可能因为当前路径不确定而找不到文件写在哪里。

让我们首先统计这个文件中的记录总数。

| =0 |
| =file("data.txt").cursor@t() |
| for |
| =B1.fetch(10000) |
| if B2==null |
| break |
| >A1+=B2.len() |

cursor() 函数会打开文件并创建一个游标（也是一个复杂对象），@t 表示文件的第一行是标题。游标的 fetch() 函数会读出由指定数量记录组成的表序列（以标题为字段名）并向前移动。下一次 fetch() 将是下一批记录。如果在读取过程中遇到文件末尾，将读出所有剩余记录，因此可能不会总是读出所需数量的记录。当没有东西可读时（文件末尾），将返回 null。

如果理解了上述知识，这段代码就很容易理解。做一个无限循环，每次读取 10000 条记录，读完后跳出循环。在过程中，累加每次读取的记录数得到结果，存储在 A1 中。

在此基础上，让我们计算平均订单金额：

| =0 |
| =file("data.txt").cursor@t() |
| =0 |
| for |
| =B1.fetch(10000) |
| if B2==null |
| break |
| >A1+=B2.len() |
| >C1+=B2.sum(amount) |
| =C1/A1 |

sum 也可以在同一个循环中计算。

要计算 sum，我们只需要读取 amount 字段；要统计记录数，随机读取一个字段就够了。没有必要读取所有字段。如果读取的少，速度会更快（从前面的讨论可以看出，从硬盘读取的数据量几乎相同，但读取更少的字段会使文件读取的处理更容易）：

| =0 |
| =file("data.txt").cursor@t(amount) |
| =0 |
| for |
| =B1.fetch(10000) |
| if B2==null |
| break |
| >A1+=B2.len() |
| >C1+=B2.sum(amount) |
| =C1/A1 |

我们可以在 cursor() 函数的参数中写入要读取的字段，这样 fetch 出来的表序列就只有几个字段，不必要的字段不必读入。这是外存计算与内存计算的一个重要区别。我们在内存计算中从不关注这个问题。

这个无限循环的结构是一个固定模式。每次写都有点麻烦。另外，可能会发生 B3 忘记写或写错的情况，这将真正变成无限循环。SPL 实际上支持直接对游标进行循环：

| =0 |
| =file("data.txt").cursor@t(amount) |
| =0 |
| for B1,10000 |
| >A1+=A2.len() |
| >C1+=A2.sum(amount) |
| =C1/A1 |

for 语句可以遍历游标，后面的整数是每个循环读出的记录数，循环变量是读入的表序列。当数据无法读出时，循环会自然停止，所以不需要写 fetch() 和结束条件，代码更简单。

使用循环，游标中的数据（实际上是用于创建游标的文件中的数据，我们后面会经常这样说）被依次完整读取。这个操作过程称为游标的**遍历**。回顾前面的规则，游标遍历只能向前移动，只能遍历一次。游标中的所有数据被读取一次后，游标遍历结束，游标就没用了，不能再读取数据。要从头再次读取数据，必须重新创建一个新游标。
