## 提取内容

要只统计记录数，SPL 也有 skip() 函数。

| =file("data.txt").cursor@t() |
| =A1.skip() |

skip() 的目的是跳过若干条记录而不读取，并返回跳过的记录数。当没有参数时，它会跳到末尾，返回的跳过记录数就是总记录数。

看来直接使用游标上的函数会更容易。像 sum 这样的操作有对应的游标函数吗？毕竟，自己写循环还是很麻烦的。例如，你需要为 sum 和 max 设置初始值。

SPL 没有游标的 sum 函数，但有 groups()。上一节的平均订单金额可以这样写：

| =file("data.txt").cursor@t(amount) |
| =A1.groups(;sum(amount):S,count(amount):C) |
| =A2.S/A2.C |

我们学过，当 groups() 函数的第一个参数填空时，表示将整个数据表分成一组，相当于对整个表进行汇总，所以可以记录所有记录的订单金额和数量。A2 的结果集是一个只有一行记录的数据表，通过 A3 的计算得到平均值（从记录序列获取字段值时默认会选择第一个成员的字段）。

为什么不像序列那样为游标提供 sum() 和 count() 函数？

因为游标遍历非常慢，我们应该在遍历过程中尽可能多地计算结果。如果我们提供 sum() 和 count() 等函数，sum() 需要遍历一次游标，count() 又需要遍历一次，性能会非常差。在代码中创建新游标也很麻烦，所以 SPL 根本不提供它。直接在 groups() 中一次遍历计算多个结果。

然而，如果我们总是使用 groups() 来汇总整个表，它总是返回一个只有一行记录的表序列。虽然使用上没有问题，但感觉还是不太好。而且我们还需要获取新的字段名，有点麻烦。因此，SPL 提供了 total 函数，可以稍微简化：

| =file("data.txt").cursor@t(amount) |
| =A1.total(sum(amount),count(amount)) |
| =A2(1)/A2(2) |

total() 函数也要求一次遍历计算多个值，但它作为序列返回，不使用字段名。

既然是 groups() 函数，它也可以用于分组聚合吗？

是的，例如，我们可以计算每个地区的订单总金额和订单数量：

| =file("data.txt").cursor@t(area,amount) |
| =A1.groups(area;sum(amount):S,count(amount):C) |

注意这次也要获取 area 字段。

看起来对游标做分组聚合和之前对表序列或记录序列做分组聚合在代码上没有区别。

确实如此，但游标仍然是特殊的。例如，我们想再按月分组。如果是记录序列，只需再写一个 groups()。但如果是游标，就不能再用了。它已经遍历完了，无法获取记录。这时，我们需要重新创建一个新游标，然后做 groups()。

| =file("data.txt").cursor@t(area,amount) |
| =A1.groups(area;sum(amount):S,count(amount):C) |
| =file("data.txt").cursor@t(dt,amount) |
| =A3.groups(month@y(dt);sum(amount):S,count(amount):C) |

但这样，游标数据被遍历了两次，速度相对较慢。

确实存在这个问题。SPL 也提供了一种在一次游标遍历过程中计算多组聚合值的方法，称为**遍历复用**。然而，这些内容属于性能优化的范畴，需要添加新概念才能解释清楚。它们超出了本书的设计大纲，所以这里不讨论。如果有兴趣，可以参考 SPL 的其他文档。

如果使用 SQL，只能遍历多次。它不支持遍历复用。

游标有 groups() 函数，但没有对应的 group() 函数（实际上 SPL 也有这个函数，但使用条件有限，与 groups() 不对应。我们将在下一节提到）。换句话说，游标的 groups() 函数不是先用 group() 函数分成子集，然后再汇总。为什么？

因为没有必要，实际上表序列和记录序列的 groups() 函数也不是先分成分组子集再进行汇总计算。有很多汇总计算，如 sum、count、max 等，可以通过在循环中依次访问集合成员来实现。每个成员只使用一次，不需要我们前面提到的随机访问，所以操作效率更高。如果你仔细阅读了第 5 章的迭代函数，你会更透彻地理解这个原理。

那么为什么游标没有对应的 group() 函数？

引入游标是为了处理无法加载到内存中的大数据。如果原始数据表无法加载到内存中，显然也不可能加载所有分组子集。如果提供 group() 函数，就需要将这些分组子集保存在外存中，性能非常差，也非常麻烦。对于必须通过分组子集实现的操作，我们会想其他更好的方法来做，所以不提供这个操作。

现在我们理解了游标上的聚合和分组操作，让我们继续看其他操作。

select() 函数在游标上会是什么样子？例如，我们想找到订单金额超过 5000 的订单。

这时，与序列和记录序列的操作非常不同。对于记录序列的选择函数，直接计算出结果记录序列，我们可以查看成员。然而，对于游标不能这样做。因为游标对应大数据，选择的结果可能仍然是大数据。我们不能把它计算成内存中的表序列。它也必须是游标。因此，游标上的 select() 函数仍然返回游标。

那么，我们如何查看选择的结果？

我们使用 fetch()。由于选择后的游标仍然是游标，我们也可以使用 fetch() 函数获取数据。然而，因为它是游标，我们不能获取所有数据，每次只能获取一部分。

| =file("data.txt").cursor@t() |
| =A1.select(amount>=5000) |
| =A2.fetch(100) |

A2 对游标进行条件过滤，仍然返回游标。然后 A3 可以获取由 100 条记录组成的表序列来检查。

当你执行这段代码时，你可以看看 A2 的返回值，发现它是一个奇怪的东西。在没有 fetch 之前，你看不到游标中的数据。反正无法显示，所以 SPL 只是将其显示为内部对象的名称。

然而，对游标执行 select() 函数到底意味着什么？它会遍历游标中的数据一次吗？

应该不会。否则，在遍历过程中符合条件的记录放在哪里？正如我们所说，它不能加载到内存中，要放到硬盘上吗？

SPL 不这样做，也没有必要这样做。游标的 select() 函数实际上不做任何实质性的选择动作。它只是记住游标上有一个选择动作要做。只有在获取数据时，SPL 才会检查游标上有一个 select() 动作，然后才会真正执行条件判断来选择记录。选择完 fetch() 所需的记录（例如这里的 100 条记录）后，它停止计算，等待下一次 fetch() 再次计算。

select() 函数返回的游标称为**延迟游标**。它只有在真正获取数据时才会执行实质性计算。这与刚才提到的 groups() 不同。groups() 会立即触发游标遍历动作，返回的不再是游标。

学习游标函数时，你应该知道它的返回值以及它是否是延迟游标。

延迟游标技术允许游标相关代码的编写方式与记录序列的计算非常相似。例如，我们想按地区对金额超过 5000 的订单进行分组汇总。如果是记录序列，我们知道只需 select() 然后 groups()；游标也是如此：

| =file("data.txt").cursor@t() |
| =A1.select(amount>=5000).groups(area;sum(amount):S) |

与记录序列的操作完全相同，非常简单。

因此，我们通常可以不太关注这些函数返回的游标是否是延迟的。简单理解为这些函数正在执行相应的计算，一般没有问题。然而，我们仍然需要知道这个机制，这在仔细分析某些代码的运行结果时是必要的。

然而，游标与记录序列仍然有一个关键区别。

在我们对某个记录序列执行 select() 后，我们会得到一个新的记录序列，但原来的记录序列不会改变，我们仍然可以继续做各种其他计算。对游标执行 select() 后得到的新游标与原游标相关。在遍历新游标的过程中，原游标也会同时被遍历。当新游标被遍历完不能重用时，原游标也会被遍历完不能重用。反过来，遍历原游标也会影响新游标。在对游标执行函数得到新的延迟游标后，原则上不应该再使用原游标，否则会有非常混乱的后果。

游标和记录序列本质上是不同的。毕竟，内存和外存之间有很大的差异。SPL 只是尽量使它们相似，这样学习和编写代码会更方便。

因为游标不能随机访问，定位是没有意义的，所以游标上没有 pselect() 这样的函数。另外，align() 和 enum() 函数通常只与小数据相关，所以没有对应的游标版本。

但 new()、run() 和 derive() 函数非常有意义。这些也是延迟游标。

例如，我们为订单金额超过 5000 的订单添加一个平均单价字段：

| =file("data.txt").cursor@t() |
| =A1.select(amount>=5000) |
| =A2.derive(amount/quantity:price) |
| =A3.fetch(100) |

我们可以基于延迟游标创建另一个延迟游标。SPL 不会立即计算，而是标记游标上有一个 select() 动作和一个 derive() 动作，在获取时会逐一执行。

new() 和 run() 类似。实际上，用于展开的 news() 也可以在游标上执行。这里不再举更多例子。

外键相关的 switch() 和 join() 对游标是有意义的。

假设每个地区都有自己的税率，现在我们想按月计算税额超过 100 的订单的总数和金额。

| [East,West,North,South,Center] |
| [0.05,0.06,0.03,0.04,0.08] |
| =A1.new(~:area,A2(#):taxrate).keys(area) |
| =file("data.txt").cursor@t() |
| =A4.switch(area,A3).select(area.taxrate*amount>100) |
| =A5.groups(month@y(dt):ym;sum(amount):S,count(amount):C) |

switch() 也返回延迟游标。在 groups() 计算过程中，只有当数据被读入时才会实际处理 switch()，即将外键字段 area 转换为维表的记录。

同样，我们想为金额超过 5000 的订单添加一个税额字段并写入另一个文件。

| … |
| =A4.select(amount>5000) |
| =A5.join(area,A3,taxrate:tax).run(tax=tax*amount) |
| >file("data.csv").export@ct(A6) |

export() 函数可以将游标直接写入文件，@c 表示写成逗号分隔的 csv 文件，@t 表示将字段名作为第一行写成标题。在 A6 中，我们首先使用 join() 函数将税率添加到游标数据中，然后使用 run 将税率改为税额。延迟游标的函数可以在多个步骤中使用，写法与内存中的记录序列完全相同。
