## 提取内容

我们还没有学习大数据的排序。

排序操作非常不同。它的计算结果与源数据一样大。如果源数据无法加载到内存中，结果肯定也无法加载，但与 select() 和 new() 不同，它不能边遍历边计算。

大数据的排序只能通过使用外存作为缓冲区来解决。一般步骤如下：读入一些数据，在内存中排序并写出结果；然后读取下一部分，排序并写出；……；最后，会得到一批有序的中间结果，然后使用归并算法将这些中间结果连接起来。这个过程很复杂，超出了本书的设计范围，这里不讲详细原理。

SPL 提供了 sortx() 函数来执行大数据排序。这个函数实现了上述所有系列过程。因为排序结果仍然是大数据，sortx() 也会返回游标，但它不是延迟游标。sortx() 会立即计算，返回的游标基于上述中间结果。

例如，我们想按平均单价从大到小排列订单数据，然后写入另一个文件：

| =file("data.txt").cursor@t() |
| =A1.sortx(-amount/quantity) |
| =file("data.csv").export@ct(A2) |

因为排序是从大到小，sortx() 使用负数作为参数。计算后的 A2 是游标，不能直接查看。你可以用 fetch() 获取数据或像 A3 一样写入另一个文件。

sortx() 立即计算。执行返回后，游标 A1 已经被遍历。此时，即使删除 data.txt 也不会影响 A3 的动作。这与 select() 等函数完全不同。select() 函数返回的延迟游标将来会与其基础游标同步遍历。

提醒一下，sortx() 可能很慢，运行后需要等待一段时间。它还会占用一些硬盘空间（用于存储中间结果）。esProc 默认会使用操作系统临时目录，你也可以在选项中自己设置临时目录。

实际上，大数据的排序本身并不常用。我们通常不关心大数据的完整排序结果，只关心前 N 个。然而，排序通常是其他大数据操作的基础。没有有序的结果，其他操作很难做。

例如，大分组。

对于我们之前使用的 groups() 函数，返回的结果是表序列，即小数据。然而，仍然有某种分组聚合操作，它的返回结果会大到内存装不下。这时，没有办法使用 groups()，会导致内存溢出。

然而，正如我们之前所说，如果数据对分组键值是有序的，我们可以使用 group() 函数的方法，在遍历过程中同时汇总，就不会溢出。无论返回的分组结果有多大，都可以正常计算。

例如，我们想按 amount 和 quantity 两个字段分组，看看每组有多少订单具有不同的 amount 和 quantity。分组结果可能有 100 万行（不大，但我们就当它大。假设用 groups() 做不了）。

当前数据对这两个字段的组合没有顺序。排序后，我们可以使用 group() 函数。

| =file("data.txt").cursor@t() |
| =A1.sortx(amount,quantity) |
| =A2.group(amount,quantity) |
| =A3.new(amount,quantity,~.count(1):C) |
| =A3.fetch(100) |

这样，我们可以计算出大分组，但因为结果很大，我们只能 fetch() 一部分来查看或写入另一个文件。

我们可以基于它做其他计算。例如，我们想计算 amount 和 quantity 相同的订单超过 5 个的组的总金额和数量（即 A4 中汇总字段 C>5）。

| =file("data.txt").cursor@t() |
| =A1.sortx(amount,quantity) |
| =A2.group(amount,quantity) |
| =A3.new(amount,quantity,~.count(1):C) |
| =A4.select(C>5).total(sum(C*amount),sum(C*quantity)) |

group() 函数返回延迟游标。我们可以附加另一个 select() 操作，然后用 total() 遍历它。

因为大分组常用，SPL 提供了 groupx() 函数，它将排序和分组一起做。上面的代码可以简化为：

| =file("data.txt").cursor@t() |
| =A1.groupx(amount,quantity;count(1):C) |
| =A2.select(C>5).total(sum(C*amount),sum(C*quantity)) |

groupx() 的参数规则与 groups() 相同，但它假设返回的结果集很大，所以会先排序（实际上更复杂），然后做有序分组，最后返回游标。像 sortx() 一样，这不是延迟游标。当两个动作一起执行时，不仅语法更简单，执行速度也更好。然而，像 sortx() 一样，它会临时占用硬盘空间。

除了大分组，还有大归并计算。

与之前归并计算的例子类似，如果我们手上有两个大订单文件，需要合并它们（或计算交集），数据必须事先有序。

| =T@c("data1.txt") |
| =T@c("data2.txt") |
| =[A1,B1].mergex@u(id) |
| >T@c("all.csv",A2) |

假设数据按 id 有序，我们可以直接使用 mergex() 计算并集。这里的参数与 merge() 相同，但通常我们不会在游标上建立主键，所以需要写归并操作中使用的关联键。

因为结果集可能很大，mergex() 也返回游标，但它是延迟游标，不会自动遍历。与 select() 函数不同，mergex() 可能为多个基础游标生成延迟游标。遍历它后，也会遍历所有基础游标。之前提到的 select() 等函数只有一个基础游标。

T() 函数使用 @c 选项生成游标，它会根据文件扩展名自动选择打开方式。它也可以用于写出，@c 表示写出游标，写出方式也会根据文件扩展名选择。

与内存中的 merge() 函数不同，mergex() 要求游标数据必须有序才能工作，没有 @o 选项。

排序后，只能通过随机访问实现的操作可以改为顺序访问。另一个类似的情况是连接操作。用关联键值查找关联记录原本需要随机访问（在数据表中搜索），但如果数据对关联键有序，顺序访问可以达到目的。

SPL 还提供了带 x 的 joinx() 函数来解决大连接。

| =T@c("data1.txt") |
| =T@c("data2.txt") |
| =joinx(A1:a,id;B1:b,id) |
| =A2.fetch(100) |

joinx() 可以支持同维关联和主子关联。它也返回延迟游标。从它 fetch 出的表序列的形式与内存中的 join() 类似。每个字段的值是每个关联游标中的记录，然后你可以继续使用 new() 函数实现进一步的引用计算。

同样，joinx() 用 @1 和 @f 支持左连接和全连接。这里不再给出详细例子。你可以生成两个不同结构的数据表来尝试做大连接，需要确保关联键是有序的，否则应该先用 sortx() 排序。

你可能发现还有一种情况我们没有提到，即在外键关联的情况下，维表太大无法加载到内存中。当我们讨论游标上与外键相关的 switch() 和 join() 时，事实表数据来自游标，但维表仍然是内存中的表序列。

在这种情况下，目前外键只能理解为连接操作，然后用 joinx() 实现。如果数据事先对事实表的外键和维表的主键无序，需要先排序。而且，每个 joinx() 只能解决一个外键关联，多个外键必须做多次 joinx()。而内存维表的 switch() 和 join() 可以在一次遍历中解决多个外键。

与只对一个游标工作的 select()、groupx() 等函数不同，mergex 和 joinx 对多个游标工作。那么，是否可以将大数据和小数据一起归并和连接？

确实存在。大数据和小数据的归并和连接操作也是大数据，应该使用大数据的方法。在这种情况下，内存中的小数据，即表序列，应该转换为游标，然后使用游标方法进行操作。SPL 提供了 cursor() 函数将表序列或记录序列转换为游标，这样内存中的小数据可以模拟成大数据，与文件游标一起操作。这里不再举更多例子。需要时可以参考相关帮助文档。

我们现在已经学会了使用游标实现大数据操作，但我们只能做对。大数据计算的另一个重要目标是做快，这也是一个非常复杂的任务，甚至是更复杂的任务。像之前提到的遍历复用技术，这些内容远超本书的设计范围。这里，我们只是给你一个印象。如何提高大数据操作性能的内容足以写另一本同样长度的书。许多计算方法需要重新设计，特别是要想办法避免实质性排序，因为排序是一个非常慢的动作。

在处理结构化数据的常规编程语言中，SQL 可以处理大数据。SQL 甚至实现了数据大小透明，即用户不需要关心数据的大小，这显然为人们省去了很多麻烦。这是 SQL 的巨大优势。然而，使用 SQL 通常需要将数据加载到数据库中，这太复杂了，超出了大多数非专业程序员的能力。

esProc 提供了对文件使用基本 SQL 的功能，可以支持大多数大数据操作，从而避免了将数据加载到数据库的麻烦。

Python 也经常用于结构化数据计算，但它没有游标对象，处理大数据时非常麻烦。相当于自己实现游标动作，这对非专业人员来说基本上是不可能的任务。
