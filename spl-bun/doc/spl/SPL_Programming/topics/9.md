2.3 注释和跳转

程序代码可能并不总是写得正确。当没有得到预期结果时，我们常常无法弄清原因。这时，我们需要调试程序来定位错误。

在早期，原始的调试方法是输出程序的中间结果，看看哪一步出错了。现代编程语言的开发环境基本上都提供了完善的调试功能，可以逐步执行代码，查看程序的方向是否与预期一致，中间结果是否与预期一致。

esProc 也提供了这些功能，都在程序菜单上。用文字描述调试功能的使用很困难。您尝试几次后就能很快掌握。我们这里不再详述。SPL 代码写在单元格中，每个执行单元是一个单元格。中途检查单元格和变量的值很容易，调试自然非常方便。

既然我们已经学习了分支结构，程序不再总是从上到下执行。它可能在不同的数据下走不同的路径。您可以使用程序调试功能来观察上述程序的方向。

在调试过程中，有时我们想看看跳过一段代码不执行时的运行效果。然而，如果我们删除这段代码，以后可能还需要加回来，这很麻烦。

在这种情况下，可以使用注释。几乎所有编程语言都提供注释语句或功能。在 SPL 中，如果一个单元格以 / 开头，它被视为注释单元格。这个单元格在执行时会被自动忽略和跳过。如果一个单元格以 // 开头，该单元格及其代码块都会被忽略和跳过。

您可以尝试在一些单元格中添加 / 或 //，看看代码显示会发生什么变化。

在下面的代码中，A7:D7 和 D5 将被忽略和跳过，即不会计算第二个解，也不会处理 B1 不为 0 的情况。

|
D
|
if A1!=0
|
=B1*B1-4*A1*C1
|
if B3>0
|
=sqrt(B3)
|
>A2=(-B1+C4)/2/A1
|
/>B2=(-B1-C4)/2/A1
|
else if B3==0
|
>A2=-B1/2/A1
|
//else if B1!=0
|
>A2=-C1/B1
|
else if C1==0
|
>output("Any")
|

使用注释来控制调试非常方便。当您不需要执行这段代码时，可以把它改成注释，需要再次执行时再改回来。代码主体不需要删除。

发明注释的初衷是让程序员能够写一些与代码相关的笔记，以防长时间后看不懂代码。当然，这个作用仍然存在，好的程序代码总是有详细清晰的注释。在 SPL 中，直接写的文本会被视为常量单元格，不影响程序的执行。它可以起到注释的作用，而注释单元格的作用更多是为了方便调试。

if 语句可以改变程序的方向，许多编程语言还提供了一种更简单粗暴的方式来改变程序流程，即 goto 语句。让我们重写求解一元二次方程的代码来感受一下（只考虑 A1 不为 0 的情况）：

|
=B1*B1-4*A1*C1
|
if A3<0
|
goto A6
|
if A3==0
|
>A2=-B1/2/A1
|
goto A6
|
=sqrt(A3)
|
>A2=(-B1+A5)/2/A1
|
>B2=(-B1-A5)/2/A1
|

代码中多了一个空行，但逻辑看起来很清晰，避免了长长的 if...else 块。

更完整的情况也可以用 goto 重写：

|
D
|
if A1==0
|
if B1==0
|
if C1==0
|
goto A9
|
>output("Any")
|
goto A9
|
>A2=-C1/B1
|
goto A9
|
=B1*B1-4*A1*C1
|
if B6<0
|
goto A9
|
if B6==0
|
>A2=-B1/2/A1
|
goto A9
|
=sqrt(B6)
|
>A2=(-B1+A8)/2/A1
|
>B2=(-B1-A8)/2/A1
|

goto 语句自诞生以来就一直有争议。许多计算机科学家抱怨它会把程序流程搞乱。当程序正常运行时，我们不知道出现 goto 语句会发生什么，当程序出错时调试非常困难。因此，一些编程语言干脆不提供 goto 语句，不允许随意跳转。

然而，有时当程序层次很深时，在条件合适的情况下，用 goto 语句跳出会使代码更清晰。如果不使用 goto，很可能要做重复判断以避免执行不应该执行的语句。我们对 goto 的态度应该是：不禁止它，但要谨慎使用。一般来说，我们可以保持这个原则：总是从多层代码的深处跳出（例如，SPL 代码块有明显的层次），而不是跳入；向前跳，而不是向后跳（虽然不禁止）。

goto 总是与 if 一起使用，即当条件成立（或不成立）时跳转。goto 如果与 if 无关，就没有意义。向前跳会使中间的代码变得无用（相反，它可以用于调试，起到前面提到的注释的作用）；向后跳程序将永远不会结束。

然而，在 SPL 中，如果您不小心写了一个不会结束的程序，不用担心。当代码运行时，开发环境不会死掉。您可以使用调试功能来终止程序。
