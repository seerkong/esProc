在 Access 文件 DbCon.accdb 中创建一个空表 CityBak：

在该表中，ID 字段是主键。已设置 POPULATION 字段的限制条件，其数据应大于 1,000,000。

（原文含示意图，图像资源未迁移）

执行 A4 时报告了错误。因为根据人口应大于 1,000,000 的限制，第 10 条记录 Detroit 不符合条件。默认情况下，当出现错误消息时，数据库操作会终止。

在这种情况下，您可以在另一个脚本文件中查看写入 CityBak 的数据：

（原文含示意图，图像资源未迁移）

虽然第一个网格中的程序执行因 CityBak 数据的限制而失败，但在第一条不符合条件的记录出现之前，一些数据已成功写入目标表。

在批量数据库更新期间发生数据库错误时，程序会停止。为了避免这种中断，可以在创建连接时使用 @e 选项，让程序自己处理错误。例如：

| | |
|---|---|
| | =demo.query("select * from CITIES") |
| | =connect@e("DbCon") |
| | >A2.execute("delete from CityBak") |
| | >A2.update(A1,CityBak,ID:CID,CITY:NAME,POPULATION,STATE:STATEID) |
| | =A2.error() |
| | =A2.query("select * from CityBak") |
| | >A2.close() |

A2 在创建数据库连接时使用 @e 选项，如果有错误，让程序自动处理，而不终止程序。为了保持数据一致性，A3 首先从 CityBak 删除现有数据。

程序执行后，A5 获得与前一次执行中 A2 相同的查询结果：

（原文含示意图，图像资源未迁移）

**注意**：一旦在批量数据库更新期间发生错误，程序将停止并报告错误。通过将 B4 中的表达式修改为 =A2.error@m()，您可以看到错误消息：

让我们更进一步：

| | |
|---|---|
| | =demo.query("select * from CITIES") |

| | >A2.update@a(A1.select(CID<6), CityBak,ID:CID,CITY:NAME, POPULATION,STATE:STATEID) |
