### 4.3.2 提交和回滚事务管理

批量更新是否成功以及哪条记录可能导致错误是不可预测的，因为每条记录的更新都会自动提交。这对数据库管理不利。

有时数据库更新事务是否应该提交或取消取决于当前情况。db.commit() 和 db.rollback() 函数分别用于执行提交和回滚。

默认情况下，esProc 语句的执行会自动提交且无法控制。为了通过 db.commit() 和 db.rollback() 控制事务提交，需要在 execute 或 update 语句中添加 @k 选项来决定应使用哪个函数。数据有效性根据错误值确定。如下例所示，如果在批量更新期间发生错误，事务将被中止。这样，数据库可以避免接收任何不可预测的结果：

| | |
|---|---|
| | =demo.query("select * from CITIES") |
| | =connect@e("DbCon") |
| | >A2.execute("delete from CityBak") |
| | >A2.update@k(A1,CityBak,ID:CID,CITY:NAME,POPULATION,STATE:STATEID) |
| if A2.error()==0 | >A2.commit() |
| else | >A2.rollback() |
| | =A2.query("select * from CityBak") |
| | >A2.update@k(A1.to(5),CityBak,ID:CID, CITY:NAME,POPULATION,STATE:STATEID) |
| if A2.error()==0 | >A2.commit() |
| else | >A2.rollback() |
| | =A2.query("select * from CityBak") |
| | >A2.close() |
