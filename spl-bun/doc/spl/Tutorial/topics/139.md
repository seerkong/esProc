# 4.6.2 四种事务隔离级别

## 内容

### 4.6.2 四种事务隔离级别

事务隔离级别决定了当存在并发执行的事务试图更新数据库中的数据时，一个数据访问操作所做的更改是否可见。esProc 将事务定义为在一个数据库连接中执行的一组 SQL 语句。

通常，只有在事务中执行相应的 TCL 语句时，数据才会被提交或回滚。但是，当在事务中执行 DDL 语句时，将自动执行 COMMIT 以将未存储的数据更新到数据库中。例如，对于在数据库中创建表的 CREATE TABLE 语句，将自动执行 COMMIT 操作。

有四种事务隔离级别：

1. **读已提交（Read committed）**。这是大多数数据库支持的默认隔离级别。它允许事务读取已提交的数据。

2. **读未提交（Read uncommitted）**。该隔离级别允许每个事务读取任何其他正在运行的事务的未提交数据。事务读取的数据可能不是最终结果，这称为脏读。

3. **可重复读（Repeatable read）**。该隔离级别允许一个事务中的多个并行实例读取相同的数据。这些实例可能相互影响并导致幻读。

4. **可串行化（Serializable）**。这是最高的隔离级别。它保证并发事务的可串行化执行，防止脏读或幻读，但由于时间覆盖或共享锁竞争，效率最低。

esProc 支持在 connect 函数中使用选项来指定不同的事务隔离级别 - @c 表示读已提交，@u 表示读未提交，@r 表示可重复读，@s 表示可串行化。

esProc 还提供 db.isolate() 函数来获取现有数据库连接中的事务隔离级别，或通过添加不同的选项来更改隔离级别。
