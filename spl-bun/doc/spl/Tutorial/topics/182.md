## 内容

6.8.3 esProc 企业版函数

在上一节中，我们提到了一些仅适用于 esProc 企业版的函数。这里让我们深入了解它们。

| [Moore,Wilson,Johnson,Smith] |
| =ifpure(A1) |
| =A1.i() |
| =ifpure(A2) |
| =demo.query("select EID, NAME, BIRTHDAY from employee") |
| =ifpure(A3) |
| =A3.i() |
| =ifpure(A4) |
| =A4.o() |
| =ifpure(A5) |

esProc 企业版允许使用纯序列。与普通序列不同，纯序列要求所有成员具有相同的数据类型。我们可以使用 A.i() 函数将普通序列 A 转换为纯序列，使用 ifpure(A) 函数判断序列 A 是否为纯序列。以下是 A1、B1、A2 和 B2 的结果：

（原文含示意图，图像资源未迁移）

我们可以看到普通序列和纯序列的显示方式相同。我们只能使用 ifpure() 函数来判断它是否为纯序列。

与纯序列类似，如果序表中的某个字段的值具有相同的数据类型，该字段称为纯字段。如果序表强制所有字段都是纯字段，则称为纯序表。请注意，纯序表使用列式存储。我们可以使用 T.i() 函数将普通序表 T 转换为纯序表，使用 ifpure(T) 函数判断序表 T 是否为纯序表。纯序表和普通序表外观相同，我们只能使用 ifpure() 函数来判断序表的类型。

我们还可以使用 A.o() 函数或 T.o() 函数将纯序列 A 或纯序表 T 转换为普通序列/序表。

现在让我们看看纯序列和普通序列之间的区别：

| [Moore,Wilson,Johnson,Smith] |
| =A1.i() |
| >A1.insert(0,12) |
| >B1.insert(0,12) |

执行 A2 后，A1 的数据自然被修改。纯序列要求所有成员具有相同的数据类型。它不允许插入其他类型的数据或将成员的类型更改为其他类型。因此，上述代码中 B2 的命令无法执行，会弹出错误报告。

纯序表也有类似的情况：

| =demo.query("select EID, NAME, BIRTHDAY from employee") |
| =A1.i() |
| >A1(1).BIRTHDAY=20001231 |
| >B1(1).BIRTHDAY=20001231 |

A2 更改第一条记录中的字段值。与纯序列不同，由于序表的每个字段都是纯序列，因此不能使用 insert 和 delete 命令向其添加或删除记录。如果更改序表中的字段值，则要求其数据类型保持不变。例如，尝试执行 B2 时会报错。

由于纯序列/序表中只有一种数据类型，因此对其进行定位操作的效率明显更高，例如：

| =demo.query("select EID, NAME, BIRTHDAY from employee") |
| =A1.i() |
| =A1.(NAME) |
| =100000.(C1(rand(500)+1)) |
| =now() |
| =A2.(A1.pselect@1(NAME:A2.~)) |
| =now() |
| =interval@ms(B2, B3) |
| =A2.(B1.pselect@1(NAME:A2.~)) |
| =now() |
| =interval@ms(B3, B4) |

A1 是普通序表；B1 是纯序表。A2 随机生成 100,000 个 NAME 值。A3 和 A4 分别从普通序表和纯序表的 EID 字段获取每个 NAME 值的位置。它们的结果相同。C3 和 C4 查找并比较执行定位所花费的时间。可以看出，在纯序表中查找目标数据所需的时间要短得多。

需要记住的一点是：纯序表中的数据是列式存储的，记录需要根据位置从每列获取数据。因此，即使定位速度快，性能也会受到影响。

| =demo.query("select EID, NAME, BIRTHDAY from employee") |
| =A1.i() |
| =A1.(NAME) |
| =100000.(C1(rand(500)+1)) |
| =now() |
| =A2.(A1.select@1(NAME:A2.~)) |
| =now() |
| =interval@ms(B2, B3) |
| =A2.(B1.select@1(NAME:A2.~)) |
| =now() |
| =interval@ms(B3, B4) |

在此示例代码中，A3 和 A4 使用 select 函数 T.select() 而不是定位函数 T.pselect()，两者都返回由记录组成的相同记录序列。区别在于 A4 结果集中的记录都来自纯序表。由纯序表记录组成的记录序列称为纯记录序列。它需要从每列获取数据才能显示。在这种情况下，纯序表完全没有优势。因此，我们应该根据实际情况选择使用纯序列/序表。

通常，从数据库查询的表的每个字段都具有相同的数据类型。db.query(sql) 函数可以使用 @v 选项直接返回纯序表结果：

| =demo.query@v("select EID, NAME, BIRTHDAY from employee") |
| =ifpure(A1) |
| =A1.select(left(NAME,1)=="J") |
| =ifpure(A2) |
| =A1.select@v(left(NAME,1)=="J") |
| =ifpure(A3) |
| [Rebacca, Matthew, Smith] |
| =A4.(A1.select@v(NAME==A4.~)).conj() |
| =ifpure(A5) |
| =A4.(A1.select@v(NAME==A4.~)).conj@v() |
| =ifpure(A6) |
| =A6.sort@v(BIRTHDAY) |
| =ifpure(A7) |

T.select(sql) 函数在对纯序表执行计算时返回纯记录序列，这是由来自纯序表的记录组成的普通序列。它可以使用 @v 选项返回纯序表。类似地，我们可以对纯序列 A 使用 A.select@v(...) 来获取纯序列。

默认情况下，连接多个纯序列的结果是普通序列。我们也可以在 A.conj(...) 函数中使用 @v 选项来获取纯序表。

我们还可以使用 T.sort@v(...) 函数和 P.sort@v(...) 函数对纯序表 T 或纯记录序列 P 的记录进行排序，并将结果作为纯序表返回。

T.new(...) 函数和 T.derive(...) 函数在从纯序表生成新序表时仍会返回纯序表。通过使用 @o 选项，我们可以利用表中的现有列来提高效率。例如：

| =demo.query@v("select NAME, SURNAME, STATE, DEPT from employee") |
| =1000.(A1).conj@v() |
| =now() |
| =ifpure(A2) |
| =A2.new(#:ID, NAME/" "/SURNAME:FullName, STATE, DEPT) |
| =now() |
| =ifpure(A3) |
| =A2.new@o(#:ID, NAME/" "/SURNAME:FullName, STATE, DEPT) |
| =now() |
| =ifpure(A4) |
| =interval@ms(B2,B3) |
| =interval@ms(B3,B4) |
| >A2(1).NAME = "New Name" |
| >A2(1).STATE = "New State" |

A1 的数据量相对较小，A2 将其复制 1,000 次后生成纯序表。A3 和 A4 都使用 T.new(...) 函数生成新序表。区别在于 A4 使用 @o 选项来启用使用 A2 中的现有列生成新的纯序表。为此，第 6 行修改了 A2 第一条记录的 NAME 字段和 STATE 字段。执行后，A3 和 A4 生成新的序表。

尽管原始序表 A2 在生成新序表后被修改，但根据上述结果，A4 结果集中第一条记录的 STATE 字段也发生了变化。这是因为 A4 与 A2 共享 STATE 字段。然而，由于 A4 的 FullName 字段是新生成的，它不受 A2 的 NAME 字段更改的影响。此外，A3 不使用 @o 选项，因此也不受数据修改的影响。

根据 C2、C3 和 C4 的结果，A2、A3 和 A4 都是纯序表。根据 A5 和 B5 获得的时间间隔，使用 @o 选项带来了更高的效率。
