## 内容

7.3.3 大结果集的分组和聚合

在上一节中，首先对多个游标分别进行分组和聚合，得到一系列按相同值排序的序表，然后将它们合并以获得最终结果。同样，您可以处理大结果集的分组和聚合。

大结果集意味着用于计算的源数据和结果集都很大。巨大的结果集无法一次性全部读入内存，而必须逐步检索。实际业务案例包括电信公司发出的每个客户的月账单和 B2C 网站上每种产品的销售额。两者的统计数据可能包含超过数百万条记录。

esProc 提供 cs.groupx() 函数来对大结果集执行分组和聚合。这里我们以产品订单的每日统计为例来说明大结果集的处理。为了更直观地了解内存限制，每次检索 100 条记录。在这种情况下，应使用 groupx 函数对每日订单进行分组和聚合：

| =file("Order_Wines.txt") |
| =file("Order_Electronics.txt") |
| =file("Order_Foods.txt") |
| =file("Order_Books.txt") |
| =[A1:A4].(~.cursor@t()) |
| =A5.conj() |
| =A6.groupx(Date;count(~):Count,sum(round(decimal(Amount),2)):TotalAmount;100) |
| =A7.fetch(100) |
| =A7.fetch(100) |
| =A7.fetch(100) |
| =A7.fetch(100) |

其中，A8~A10 的每行检索 100 天的统计数据，A11 检索其余部分。A7 游标中的数据完全取出后，游标自动关闭。

A7 使用 groupx 函数执行分组和聚合，同时将缓冲行数设置为 100。A7 的 groupx 函数中的最后一个参数表示内存最多可容纳 100 条记录，因此当内存中的记录数达到 100 时需要进行缓冲。在实际编码中，不需要该参数，因为 esProc 会自动估计可用内存可容纳的记录数，以判断是否应执行缓冲。因此，执行时，A7 从 A6 的游标获取记录，同时对它们进行汇总和聚合。一旦产生聚合 100 条记录的结果，它将被缓冲到临时文件。其余部分以相同方式完成。A7 的结果是由一组临时文件组成的游标：

这些临时文件的名称是随机生成的。从某些临时文件检索的数据来看，每个临时文件存储对一些连续原始记录进行分组和聚合的结果，并按 Date 排序。实际上，根据函数中指定的缓冲行数，除最后一个外，每个临时文件包含 100 天的聚合数据。对于使用 groupx 生成的游标，其数据将通过按一定顺序合并所有临时文件来使用 fetch 获取。

从临时文件游标完全取出数据或游标关闭后，相应的临时文件将自动删除。关于外存分组，请参阅《大结果集的外存分组方法》。
