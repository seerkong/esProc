## 内容

7.9.2 从文件游标按段获取数据

cs.fetch() 的使用在《文本文件》和《Bin 文件》中都有讨论。此外，文件分段参数可以与 cursor 或 export 函数一起使用，从文件或游标按段（或按块）检索数据。但有时由于 esProc 分段文件的方式，在数据获取期间会出现问题。

这里有一个例子。创建一个数据文件，将上述已按 PID 排序的数据保存为新的 bin 文件 Order_Products.btx：

| =file("Order_Wines.txt") |
| =file("Order_Electronics.txt") |
| =file("Order_Foods.txt") |
| =file("Order_Books.txt") |
| =[A1:A4].(~.cursor@t().sortx(PID)) |
| =A5.merge(PID) |
| =file("Order_Products.btx") |
| >A7.export@b(A6) |

然后按段检索数据：

| =file("Order_Products.btx") |
| =A1.cursor@b(;1:100) |
| =A2.fetch() |
| =A1.cursor@b(;2:100) |
| =A4.fetch() |

但出现了一个问题。对于代码号为 B1435 的产品，其销售记录出现在两个组中。如果在获取每个数据段后需要聚合操作，则返回结果中将出现重复的代码号。因此，需要重新聚合才能获得最终结果。数据分段在大数据的并行处理中很常见，这个问题使计算变得复杂。一个解决方案是在以二进制格式存储数据时通过定义分组字段来按组分段数据。

将 bin 文件存储为游标时，指定分组字段可确保数据在导出时按组分段。一组记录将被分组在一起，直到分组字段的值变得不同。因此，同一组的数据将在分段检索时一次性全部获取。例如：

| =file("Order_Wines.txt") |
| =file("Order_Electronics.txt") |
| =file("Order_Foods.txt") |
| =file("Order_Books.txt") |
| =[A1:A4].(~.cursor@t().sortx(PID)) |
| =A5.merge(PID) |
| =file("Order_Products_G.btx") |
| >A7.export@b(A6;PID) |

将已按 PID 排序的数据存储为 bin 文件 Order_Products_G.btx，并根据 PID 按组分段。这与之前从文件 Order_Products.btx 导出数据的方法略有不同。请注意，分段存储仅在为存储指定分段字段时有效。原始数据按其分组的字段在导出时通过函数中的参数指定。例如，A8 指定 A6 的游标根据 PID 按组分段，在这种情况下，游标数据必须按分组字段排序。

现在，如果我们按段获取数据，结果将不同：

| =file("Order_Products_G.btx") |
| =A1.cursor@b(;1:100) |
| =A2.fetch() |
| =A1.cursor@b(;2:100) |
| =A4.fetch() |

通常，检索存储为游标的 bin 文件与读取普通文件相同。但由于数据在导出时按组分段，数据获取结果变得不同，如 A3 和 A5 这次所示：

ID 为 B1445 的产品的销售记录将全部从第一段获取，第二段将从下一个产品 ID 开始获取。因此，如果 export() 函数在将 bin 文件导出为游标时指定按组分段，则在获取游标时，同一组数据将作为一个段被检索。按组分段数据保证了每个段中数据的完整性，并使按段处理大数据更简单、更容易。
