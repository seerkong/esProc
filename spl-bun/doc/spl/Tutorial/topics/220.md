## 内容

7.10.4 应用

通过调用网格文件，跨网格游标执行计算并将结果作为游标返回。这允许我们使用网格文件处理一些复杂的数据处理任务。例如，在大数据分析和处理过程中，文本数据通常用作源数据。但由于它不像数据库数据那样有序，因此应通过例程重新排列。在这种情况下，跨网格游标用于调用这个单独的例程。

D:\files\EmployeeMul.txt 包含员工数据，如下所示：

| 1 | Nicole Jones | F | 2009-08-01 |
| 1990-01-03 | Philadelphia | Pennsylvania | Production |
| 0 | NicoleJones_PA@mail.xxx | |
| ... |

在此文本文件中，每个员工的数据在三行中包含 ID、姓名、性别、入职日期、生日和城市等信息。文本文件将具有多个字段的记录保存在多行中是很常见的。任务是从文件中找到费城员工的数据。

文本文件不能直接用于计算，因为 esProc 要求在直接将文本数据导入为序表或游标时，文件中的每行数据都是一条记录。EmployeeMul.txt 文件中的数据应在文件可用于分析和计算之前重新组织。如果使用跨网格游标，程序将更加直观。首先可以在 mergeRecord.splx 中重新组织数据：

| D |
| =file("EmployeeMul.txt").cursor() |
| for A1,5000*3 |
| =A2.step(3,1) |
| =A2.step(3,2) |
| =A2.step(3,3) |
| =join@p(B2:L1;C2:L2;D2:L3) |
| =B3.new(L1.#1:ID,L1.#2:Name,L1.#3:Gender,L1.#4:EntryDate,L2.#1:Birthday,L2.#2:City,L2.#3:State,L2.#4:Dept,L3.#1:SuperiorID,L3.#2:MailAdress) |
| return C3 |

A1 将文本文件导入为游标。A2 每次获取 5000*3 条记录，并在其语句块内连接获取的数据。对于每三条记录，B2、C2 和 D2 分别获取第一条、第二条和第三条来创建记录序列。B3 使用 join@p 函数连接三个序表。之后 C3 可以使用源数据生成所需的记录。

然后通过跨网格游标调用 mergeRecord.splx 可以轻松处理任务所需的计算。

| =cursor("mergeRecord.splx") |
| =A1.select(City=="Philadelphia") |
| =A2.fetch() |

有时文本数据除了需要将多行数据组合成一条记录外，还具有更复杂的格式，如以下 D:\files\mailInfo.txt 所示：

（原文含示意图，图像资源未迁移）

该文件包含电子邮件，包括收件人地址、发件人地址和内容，分别以 RECIPIENT:、SENDADDRESS: 和 CONTENT: 开头。由于每封邮件内容的行数不同，因此无法导入和组合指定数量的数据行并直接使用它们。然而 esProc 支持跨网格游标，通过它可以先在另一个网格 readMail.splx 中重新组织数据：

| =file("mailInfo.txt").cursor@s() |
| >A1.skip(2) |
| ="" |
| for A1,5000 |
| =C1+A2.(#1).concat("\r\n") |
| =B2.split("RECIPIENT:") |
| if A1.fetch@0(1) |
| =C2.len() |
| >C1="RECIPIENT:"+C2(C3)+"\r\n" |
| >C2=C2.to(2,C3-1) |
| else |
| >C2=C2.to(2) |
| =C2.regex("(.+)[\\s\\S]+"+"SENDADDRESS:(.+)[\\s\\S]+"+"CONTENT:([\\s\\S]+)" Recipient,SendAddress,Content) |
| return B7 |

A1 基于文本文件创建游标。B1 跳过前两行无意义的数据。由于无法预先确定文本文件中需要多少行才能形成一条记录，因此需要额外考虑。C1 存储每次循环留下的未处理数据。

A2 运行循环，每次从游标获取 5,000 行。B2 将获取的数据连接成一个大字符串，将前一次循环留下的未处理数据放在每批数据的开头。由于每封电子邮件以 RECIPIENT: 开头，C2 按此将大字符串拆分为序列。新创建序列的第一个成员将是空行，您无法确认其最后一个成员是否已处理。因此数据将从第 3 行到第 7 行继续处理。B3 在 cs.fetch() 函数中使用 @0 选项来判断游标数据是否已全部取出，而不是真正从游标获取数据。如果没有全部取出，剩余数据将存储在 C1 中。

B7 使用 regex 函数对 C2 中的每行数据执行正则表达式解析。根据另外两个关键字 SENDADDRESS: 和 CONTENT:，它获取所需的数据并使它们成为字段值。由于这里使用的正则表达式字符串很长，因此将其拆分为多个较小的字符串以便于查看。

B8 将每批的解析结果返回给主程序。

尽管解析过程很复杂，但主程序使用跨网格游标简单地获取数据，其使用与普通游标没有任何不同。
