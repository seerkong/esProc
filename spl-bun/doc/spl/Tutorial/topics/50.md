# 2.3.3 记录序列——序表记录引用的序列

## 代码片段
```spl
=file("Order_Books.txt").import@t()
=A1.to()
=A1.select(Amount>=20000
=B1.select(Amount>=20000
=A1.sort(SalesID,-Date)
=B1.sort(SalesID,-Date)
=file("Order_Books.txt").import@t()
=A1.select(SalesID==363)
>A1.modify(3,
=file("Order_Books.txt").import@t()
>A1.modify(3,
=A1.select(SalesID==363)
```

## 内容摘要
显然，如果对序表执行的每一步计算都生成一个新的序表，将使用大量内存空间。例如，序表 Order_Books 有 50,000 条记录，通过查询获得 30,000 条记录。如果创建新的序表，内存中将有 80,000 条记录。实际上，由于查询的记录是原始序表的一部分，没有必要重新创建序表。您可以简单地将它们的引用存储在某种类型的数据对象中。esProc 用于执行此操作的数据对象是记录序列。

**记录序列的透明性**

通常，没有必要区分记录序列和序表，因为也没有必要区分引用和物理数据。例如，前面示例中的查询、排序和交集等操作可以使用相同的语法在记录序列和序表上执行：

| =file("Order_Books.txt").import@t() | =A1.to() |
| =A1.select(Amount>=20000 && month(Date)==5) | =B1.select(Amount>=20000 && month(Date)==5) |
| =A1.sort(SalesID,-Date) | =B1.sort(SalesID,-Date) |

注意：A1 是序表，B1 中的记录序列源自它。A2、B2、A3 和 B3 的结果都是记录序列。

可以在记录序列之间执行集合操作，就像在"序表——特殊的序列"中操作订单一样。但在序表之间执行集合操作没有任何实际意义，因为不同序表的成员是不同的对象，它们的交集始终为空。

当数据结构发生变化时，esProc 将自动创建新的序表，就像上面示例中使用 groups 函数对数据进行分组和聚合，或使用 derive 函数向序表添加新字段时发生的情况一样。

**从序表到记录序列的单向影响**

不同的序表持有不同的物理记录，因此修改一个序表不会影响其他序表。但是，记录序列是序表记录的引用，使用后者的物理数据作为其来源；源序表的任何更改都会影响相应的记录序列。例如：

| =file("Order_Books.txt").import@t() | =A1.select(SalesID==363) | >A1.modify(3, 1:SalesID) |

点击工具栏上的单步执行按钮，您将看到 A1 的序表，其中第三条记录的 SalesID 是 363。

A2 从序表中选择所有 SalesID 为 363 的记录并创建记录序列。

（原文含示意图，图像资源未迁移）

A3 通过将 1 重新赋值给 A1 序表的第三条记录的 SalesID 来修改它。然后检查序表，您可以看到第三条记录已被修改。

（原文含示意图，图像资源未迁移）

检查 A2 的记录序列显示相应的记录也发生了变化，尽管它没有被直接修改。这是因为它引用序表的记录作为自己的记录。

（原文含示意图，图像资源未迁移）

如果有多个记录序列使用同一个序表作为其来源，所有这些记录序列中的相应记录都会相应地发生变化。

但在许多情况下，这不是程序员想要看到的。以上述情况为例。因为 A3 对序表的修改发生在 A2 选出所需数据之后（在这种情况下，相应的引用没有改变），在 A2 中选择的数据中有一条 SalesID 不是 363 的记录。这可能会导致业务错误。

为了避免错误，您应该在创建记录序列之前完成对序表的修改。例如：

```
TSeq.modify(5, 1000: Amount) / 将 OrderID 等于 5 的记录的 Amount 字段修改为 1,000，即小于 2,000。
RSeq = TSeq.select(Amount>2000) / OrderID 等于 5 的记录不会出现在 RSeq 中。
```

| =file("Order_Books.txt").import@t() | >A1.modify(3, 1:SalesID) | =A1.select(SalesID==363) |

首先在 A2 中修改原始数据，然后选择所需数据。这样，A3 中获得的记录序列如下：

（原文含示意图，图像资源未迁移）

这个结果是业务所需要的。只要理解了序表和记录序列之间的引用关系，上述计算顺序就是自然的。

需要注意的是，修改原始序表的操作（如 modify 函数）在记录序列中不被接受。两者之间的关系是安全的单向影响，让用户完全有信心使用记录序列和序表获得正确的结果。
